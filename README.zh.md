## 🧠 这是什么？

**LeetCode 不是算法题集——它是成年人生存模拟器。**

每道经典题目背后都藏着一个模式，这个模式在面试结束很久之后依然会浮现：在你管理团队的方式里，在你和一个瓶颈博弈的过程里，在你清理一周会议日程的取舍里，在你决定该忘掉什么的时候。

这个仓库把知名的算法题重新表述为**职场课、人生课和反模式**——使用一套可复用的模板。结构每次都一样，这样你的大脑是在模式匹配，而不是死记硬背。任何人随时都可以按下面的模板添加新条目。

## 📐 模板

每个条目遵循**统一的四幕结构**——外加一个可选的附加幕：

| 幕 | 必填？ | 图标 | 它回答的问题 |
|-----|--------|------|-------------|
| **算法** | ✅ 是 | 🧩 | 这个算法到底在做什么？ |
| **职场** | ✅ 是 | 🏢 | 这个模式在工作中哪里会出现？ |
| **人生** | ✅ 是 | 🌍 | 在日常生活中哪里会出现？ |
| **反模式** | ✅ 是 | ⚠️ | 什么样的做法听起来对但其实错了？ |
| **权力博弈** | ⬜ 可选 | 🪞 | 当职场动态足够精彩、值得单独开一段时使用（例如权力、审批关卡、派系博弈） |

### 空白模板

复制以下代码块，填写后粘贴到 `## 📖 目录` 下方：

```markdown
### N. [题目名]

> *[一句话描述题目。]*

**🧩 算法**
[用通俗的语言解释算法在做什么。如果复杂度能增加直觉理解，就提一下。]

**🏢 职场**
[这个模式在工作中哪里出现？要具体——说出场景，而不仅仅是感觉。]

**🪞 权力博弈**  <!-- 可选：仅当权力动态才是真正核心时才写 -->
[当权力、审批权或派系结构是瓶颈时，在这里点出来。]

**🌍 人生**
[在工作之外哪里会出现？保持接地气——精力、人际关系、习惯、时间。]

**⚠️ 反模式**
[人们本能地会做什么、听起来对但其实是错的做法？用引号框出来，然后反驳它。]
```

### 怎样填得好

- **算法** → 先用大白话说清楚，再给复杂度记号。读者应该先理解*想法*，再看到 Big-O。
- **职场** → 说一个具体的场景（"两个例会讨论的是同一份议程"），不要说感觉（"沟通很难"）。
- **人生** → 一个接地气的例子。不要列清单。读者应该点头，而不是记笔记。
- **反模式** → 先用引号框出错误直觉，然后解释*为什么*错了。格式：*"错误直觉"* → 为什么错 → 正确做法。
- **权力博弈** → 只有当真正的瓶颈是*权力*而非*努力*时才用。如果职场课讲的是流程而非政治，就跳过。

### 1. Two Sum

> *在数组中找到两个数，使其和等于目标值。*

**🧩 算法**
暴力法检查每一对——$O(n^2)$。聪明的做法是用哈希表：对每个数，问*"我是不是已经有它的互补值了？"* 如果有，搞定。$O(n)$。

**🏢 职场**
别试图一个人解决所有问题。你的工作是维护一张心理地图：*"谁补上了我缺的东西"*——然后开口求助。找到对的人比自己硬算快得多。

**🌍 人生**
每个优势都有对应的短板。与其把弱项磨到平庸，不如找一个优势恰好覆盖你盲区的人。两个互补的普通人加起来，胜过一个累垮的全能选手。

**⚠️ 反模式**
*"我再努力一点、再熬久一点，总能找到答案。"*
有时候可以。但大多数时候答案就坐在隔壁办公室。独自搜索的成本按平方增长；开口求助的成本是常数。

### 2. Container With Most Water

> *两条线构成一个容器。最大化它们之间的面积。*

**🧩 算法**
从最宽的容器开始，向内移动**较短**的那条线。移动较长的那条永远不会增加面积——短的那条才是瓶颈。

**🏢 职场**
项目卡住的时候，别继续打磨已经够好的部分。找到瓶颈——那个人、那个审批、那个依赖——然后解决它。其他的都是装饰性努力。

**🪞 权力博弈**
如果一个人的权限决定了事情能不能推进，那其他所有人再努力都被这道门卡住了。真正的问题是权限结构，而不是等待者的执行速度。

**🌍 人生**
你可能一天有很多时间，但如果精力不足，精力就是那道短板。你每天的产出受精力限制，不受时间限制。在精疲力竭的时候优化日程表，是在移动错误的那堵墙。

**⚠️ 反模式**
*"哪边看起来更有希望就优化哪边。"*
通常是错的。你应该优化当前限制结果的那个变量。看起来有希望的那一边，往往是已经还不错的那一边。

### 3. Sliding Window

> *维护一个动态子数组；右侧加入元素，左侧淘汰元素。*

**🧩 算法**
扩展窗口直到违反约束，然后从左侧缩小直到重新满足。窗口在滑动——它不会无限增长。

**🏢 职场**
你的容量——注意力、专注时间、会议时段——就是那个窗口。新优先级来了，旧的就得走。如果不断扩大窗口却不淘汰，你就会违反约束，质量随之崩塌。

**🌍 人生**
你的精力和注意力有固定大小。对一切说"好"就是一个无界窗口。成年人的自律是知道该丢掉什么，让当前优先级真正放得下。

**⚠️ 反模式**
*"再加一件事应该没事吧。"*
加一次没问题。每周加一件，一年后窗口就溢出了。关键不在于添加，而在于及时淘汰。

### 4. Binary Search

> *在有序数组中，每步将搜索空间减半来找到目标。*

**🧩 算法**
比较中间元素和目标。丢掉不可能包含答案的那一半。重复。$O(\log n)$ 而不是 $O(n)$。

**🏢 职场**
别每次都从头排查。问自己：*"我现在能排除哪一半问题？"* 对事故二分。对 bug 二分。对组织架构二分，找到真正拍板的那个人。

**🌍 人生**
出了问题——一段关系、一个习惯、一个项目——别从头开始查。问*"问题在前半段还是后半段？"* 然后聚焦。大多数调试其实是人的调试，而人的调试也受益于二分法。

**⚠️ 反模式**
*"让我从头到尾再看一遍。"*
那是线性搜索。你在用 $O(n)$ 的成本做本该 $O(\log n)$ 的事。在看所有东西之前，先问自己哪一半可以安全跳过。

### 5. Merge Intervals

> *给定多个重叠的区间，合并为不重叠的范围。*

**🧩 算法**
按起始时间排序。如果下一个区间与当前合并范围重叠，就扩展。否则开始新区间。输出是一组干净、不重叠的范围。

**🏢 职场**
会议、职责和归属区域高度重叠时就应该合并。两个例会讨论的是同一份议程？合并。两个人负责相邻范围、边界模糊？厘清或合并。否则协调成本会爆炸。

**🌍 人生**
如果你的"和朋友叙旧"、"周日规划"和"买菜"都挤在同一个下午，就把它们当成一个整体来安排。在地理位置和精力都相邻时还分成单独时段，只是在制造开销。

**⚠️ 反模式**
*"结构越多越清晰。"*
只有在结构不重叠时才成立。五个重叠的结构比没有结构更混乱。先合并，然后只有在合并后的范围确实超出一个容器时才拆分。

### 6. Top K Frequent

> *返回数组中出现频率最高的 K 个元素。*

**🧩 算法**
统计频率，然后取前 K 个——通常用堆或桶排序。你不需要排序所有东西，只需要提取最重要的 K 个。

**🏢 职场**
你不需要回应房间里的每一个声音。找到高频、高影响的信号——每个周期都出现的利益相关者、每个迭代都复发的问题——优先处理这些。长尾可以等。

**🌍 人生**
你的大部分快乐来自少数几段关系和几个习惯。你的大部分压力来自少数几个反复出现的问题。分别找到各自的 Top K。加倍投入前者；化解后者。

**⚠️ 反模式**
*"所有反馈一视同仁。"*
对所有*反馈*都要尊重，但不要对所有*问题*同等对待。一个人提过一次的问题和十个人每周都在提的问题不是一个优先级。先排优先级，再行动。

### 7. LRU Cache

> *固定大小的缓存，满了时淘汰最久未使用的条目。*

**🧩 算法**
维护一个有界存储。访问时标记为最近使用。存储满了、新条目到来时，淘汰最久未使用的。容量固定，策略是按最近使用淘汰。

**🏢 职场**
你的工作记忆是有限的。你没法同时记住每个项目、每个同事的偏好、每个 API 的坑。健康的做法：让过期的东西自然淡忘，并且**建一套能快速重新加载的系统**。文档、Wiki、书签就是你的淘汰感知重载机制。

**🌍 人生**
忘事不是失败——是垃圾回收。技能不是"永远不忘"，而是"知道去哪儿查"。一套有条理的笔记系统意味着"我忘了"只需 $O(1)$ 修复，而不是 $O(\text{尴尬})$。

**⚠️ 反模式**
*"我应该记住所有东西。"*
不。你应该记住*索引*，需要时重新加载*内容*。试图把一切都装在脑子里的人，要么倦怠，要么在缓存溢出时死机。

### 8. Graph / DFS

> *从起点出发，通过深度优先搜索遍历所有可达节点。*

**🧩 算法**
从起始节点出发，沿每条分支尽可能深入再回溯。你访问所有通过边可达的节点——不只是你当前树里的那些。

**🏢 职场**
组织架构图是树；实际关系是图。你以为 A 向 B 汇报，但 A 还和 C 一起吃午饭、和 D 是校友、欠 E 一个人情。要理解信息和决策真正怎么流动，得遍历图——隐藏边才是影响力真正所在。

**🌍 人生**
你的社交世界不是树。你朋友的朋友的同事就隔着两跳，可能正是你需要的那条线。深度优先地探索你的网络——沿着一条线索走到底再回溯——能发现广度优先刷信息流永远刷不到的机会。

**⚠️ 反模式**
*"组织架构图告诉我谁和谁在沟通。"*
它告诉你谁*向谁汇报*。它没告诉你谁*信任*谁。信任边在图中不可见，但在现实中是决定性的。画图，别画树。

### 9. Cycle Detection

> *检测遍历是否进入了已经访问过的节点——即存在环。*

**🧩 算法**
用快慢指针（Floyd 算法）或访问集合。如果快指针追上了慢指针，或某节点再次出现在访问集合中，就存在环。

**🏢 职场**
如果你每个周一都在修上周五崩的东西——同样的故障、同样的冲突、同样的沟通失误——你不是在解决问题，你是在遍历一个环。检测它：标记节点，观察重复，然后**打断循环**，而不是重新走一遍。

**🌍 人生**
和同一个人反复就同一件事争吵就是环。出路不是"这次更努力"，而是改变图的结构，让制造循环的那条边不再存在。可能是一个新流程、一条新边界，或一次全新的对话。

**⚠️ 反模式**
*"这次会不一样的。"*
如果输入相同、结构相同，输出就会相同。你不是在解决问题——你在迭代。要么打断环，要么接受它会重复。

### 10. Union Find

> *追踪哪些元素属于同一个不相交集；按需合并集合。*

**🧩 算法**
每个元素初始各自一集。`Union` 合并两个集合。`Find` 告诉你某个元素属于哪个集合（用路径压缩提高效率）。随时间推移，单独的集合逐渐合并成更大的簇。

**🏢 职场**
办公室政治的部分真相：谁和谁其实是一派的。两个看似独立的人可能共享同一位导师、同一条预算线、或一段互相提拔的历史。Union-Find 就是这个模型：不断合并集合，直到真正的簇浮出水面——"出人意料"的联盟也就说得通了。

**🌍 人生**
社群靠合并形成。你的健身房朋友和工作朋友看似无关，直到你发现他们上的是同一所大学。集合不断合并，你的世界突然比想象中更小、更紧密。那不是巧合——那是图在收缩。

**⚠️ 反模式**
*"在证明有关联之前，每个人都是独立的。"*
大多数人已经身处一个你尚未探测到的集合中。假设隐藏的 union 边存在并主动去探测——比在冲突中才发现它们快得多。

### 11. Dijkstra

> *在边权非负的加权图中找到最短路径。*

**🧩 算法**
维护一个按当前最优已知距离排序的优先队列，存放未访问节点。反复取出最近的未访问节点，松弛其边，更新邻居。保证找到总成本最小的路径。

**🏢 职场**
最快的职业路径很少是最舒服的一串步骤。有时最短的路线要穿过一个*当下*成本更高但能大幅缩短总距离的挑战性任务。Dijkstra 优化的是**累计成本**，不是每一步的舒适度。

**🌍 人生**
通往目标的 shortest path——一项技能、一段关系、一个存款目标——往往包含一段早期不舒服的边。每一步都走舒服的路倾向于产生一条又长又贵的路径。算法在告诉你：最小化总和，而不是当前这一步。

**⚠️ 反模式**
*"每一步都选最容易的。"*
那是贪心，不是 Dijkstra。贪心会陷入局部最优。Dijkstra 愿意当下走一步成本高的，因为它知道*总成本*会更低。优化路径，不是优化单步。

### 12. Dynamic Programming

> *把问题拆成重叠子问题；存储结果以避免重复计算。*

**🧩 算法**
核心洞察：很多问题的本质不是"我现在该选什么？"而是"给定我处于这个状态，从这里出发能达到的最佳结果是什么？"你填一张子答案表，每个格子依赖前面的格子。最终答案就是表中的一个格子。

**🏢 职场**
职业决策是 DP，不是贪心。"我该不该接这份工作？"是错误的问题。正确的问题是：*"鉴于我现在的位置——技能、人脉、存款、精力——从当前状态出发能达到的最佳结果是什么？"* 你的当前状态编码了所有过去的决策。下一步只是转移函数。

**🌍 人生**
大多数人生问题是基于状态的，不是基于步骤的。*"我该不该搬家 / 转行 / 现在开始？"* 只有相对于你当前所在的位置才有意义。两个人站在同一个十字路口，最优解不同，因为他们的*状态*——存款、家属、健康、支持网络——不同。同样的步骤从不同状态出发会导向不同结果。

**⚠️ 反模式**
*"一般来说正确的选择是什么？"*
没有"一般来说正确"的选择。只有"从你当前状态出发正确"的选择。脱离状态问问题，就像不做表跑 DP——你每次都从头算，得到一个更差的答案。
