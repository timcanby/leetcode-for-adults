### 2. Container With Most Water

> *二本の線が容器を作る。その間の面積を最大化する。*

**🧩 アルゴリズム**
任意の二本の線の間の面積 = `(距離) × min(height[left], height[right])`。二つの力が競合する：広いほど良いが、短い方が水位の上限を決める。

最も広いペアから始める。ここから幅は縮むしかない。だから唯一の問いは：**どちら側を動かすか？** 長い方を動かすと——幅が減り、有効高さは短辺に制限されたまま——面積は悪くなるだけ。短い方を動かすと——幅は減るが、より高い線に出会う*かもしれない*。それが唯一の希望だ。

これは推測ではない。証明だ：短辺を保持する全ての組み合わせは、現在より悪いことが既に証明されている。各ステップで探索空間の一行全体を排除し、$O(n^2)$ を $O(n)$ に圧縮する。

```python
class Solution:
    def maxArea(self, height: list[int]) -> int:
        left, right = 0, len(height) - 1
        ans = 0

        while left < right:
            ans = max(ans, (right - left) * min(height[left], height[right]))

            if height[left] < height[right]:
                left += 1
            else:
                right -= 1

        return ans
```

> 時間 $O(n)$ · 空間 $O(1)$

**🏢 職場**
プロジェクトが停滞したら、もう十分良くなっている部分を磨き続けるな。ボトルネック——その人、その許認可、その依存先——を見つけて、そこに対処する。他は装飾的な努力だ。

**🪞 権力闘争**
一人の権限が Ship できるかどうかの門を握っているなら、他のみんなの頑張りは全員その門で頭打ちになる。チームの速度を倍にし、エンジニアを十人追加しても、産出は変わらない——短い壁はそのサインオフであって、スプリントの速度ではないからだ。本当の問題は許認可の構造であって、待っている人たちの実行速度ではない。

**🌍 人生**
一日に時間はたくさんあっても、精力が低ければ、精力が短い壁だ。一日の産出は時間ではなく精力で制限される。疲れ切っている時にカレンダーを最適化するのは、間違った壁を動かしている——幅を狭めているだけで、ボトルネックは上がっていない。

ここにより深い個人的な真実がある：**短い壁が運命を決める。** 十の分野で優秀であっても、最終的に定義されるのは最も弱い一つ——あなたの人間関係、キャリア、健康を制限するあの一つ——による。「強みを伸ばし続ける」という本能は、長い壁を動かしている。生産的に感じる。だがそうではない。

もしあなたがチームを管理しているなら：**チームの産出は最も弱いメンバーに制限される、最も強いメンバーではない。** スター選手のヒロイズムがどれほど輝いても、毎スプリントでパイプラインを詰まらせる人を補償できない。高い壁を称賛し続けても——水は短い壁から溢れる。唯一の解決策は短い壁を高くすること：トレーニング、ペアリング、メンタリング、または再編。ボトルネックを無視してピークを称えるのは、最も一般的で——最も高くつく——管理の間違いだ。

**⚠️ アンチパターン**
*"有望に見える方を最適化する。"*
頻繁に間違っている。現在結果を制約している変数を最適化すべきだ。有望に見える側は、たいてい既に上手くいっている側——それは長い壁で、動かしても何も変わらない。直面したくない、見栄えのしない側——それが短い壁だ。全てを決めるのはそっちだ。
