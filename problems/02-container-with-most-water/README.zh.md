### 2. Container With Most Water

> *两条线构成一个容器。最大化它们之间的面积。*

**🧩 算法**
任意两根线之间的面积 = `(距离) × min(height[left], height[right])`。两个力量在竞争：越宽越好，但较短的那根线决定了水位上限。

从最宽的一对开始。从此宽度只会缩小。所以唯一的问题是：**移动哪一边？** 移动较长的一边——宽度变小，有效高度仍被短边卡住——面积只会更差。移动较短的一边——你会损失宽度，但*可能*遇到更高的线。这是唯一的希望。

这不是猜的。这是证明：所有保留短边的组合都已经被证明比当前更差。每一步排除一整行搜索空间，把 $O(n^2)$ 压缩成 $O(n)$。

```python
class Solution:
    def maxArea(self, height: list[int]) -> int:
        left, right = 0, len(height) - 1
        ans = 0

        while left < right:
            ans = max(ans, (right - left) * min(height[left], height[right]))

            if height[left] < height[right]:
                left += 1
            else:
                right -= 1

        return ans
```

> 时间 $O(n)$ · 空间 $O(1)$

**🏢 职场**
项目卡住的时候，别继续打磨已经够好的部分。找到瓶颈——那个人、那个审批、那个依赖——然后解决它。其他的都是装饰性努力。

**🪞 权力博弈**
如果一个人的权限决定了事情能不能推进，那其他所有人的努力都被这道门卡住了。你可以把团队速度翻倍、再招十个工程师，产出不会变——因为短板是那个签字，不是冲刺速度。真正的问题是权限结构，而不是等待者的执行速度。

**🌍 人生**
你可能一天有很多时间，但如果精力不足，精力就是那道短板。你每天的产出受精力限制，不受时间限制。在精疲力竭的时候优化日程表，是在移动错误的那堵墙——你在缩小宽度，却没有抬高瓶颈。

这里有一个更深的个人真相：**短板决定命运。** 你可以在十个领域都很出色，但最终被定义的还是你最薄弱的那一项——它限制了你的关系、你的职业、或你的健康。不断"加长优势"的本能就是在移动长边。感觉很有成效，实际上不是。

如果你管一个团队：**团队的产出被最弱的成员限制，不是最强的。** 明星员工的英雄主义再怎么亮眼，也补偿不了每个 sprint 都卡住流水线的那个人。你可以一直夸那堵高墙——水照样从短板溢出去。唯一的解法是把短板抬高：培训、结对、指导，或者重组。忽视瓶颈却只会为巅峰鼓掌——这是最常见、也是最昂贵的管理错误。

**⚠️ 反模式**
*"哪边看起来更有希望就优化哪边。"*
通常是错的。你应该优化当前限制结果的那个变量。看起来有希望的那一边，往往是已经还不错的那一边——它是长墙，移动它什么都不改变。那个你不愿面对的、不好看的那一边——那才是短板。决定一切的就是它。
