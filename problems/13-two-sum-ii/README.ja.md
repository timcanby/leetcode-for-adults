### 13. Two Sum II

> *ソート済み配列が与えられ、合計が目標値になる二つの数を見つける。*

**🧩 アルゴリズム**
配列はソート済みだ。それは詳細ではなく——アルゴリズムの全体だ。

左ポインタを最左（最小値）に、右ポインタを最右（最大値）に置く。和を計算する。三つの状況しかない：

- `sum == target` → 完了。
- `sum < target` → 和が小さすぎる。右ポインタを左に動かすと和はさらに小さくなる（値は減少）。だから現在の左ポインタと他の任意の右端点の組み合わせは全て小さすぎる。左ポインタを淘汰し、右に動かす。
- `sum > target` → 和が大きすぎる。左ポインタを右に動かすと和はさらに大きくなる。だから現在の右ポインタと他の任意の左端点の組み合わせは全て大きすぎる。右ポインタを淘汰し、左に動かす。

各ステップは一つのペアを確認するだけでなく——**探索空間の一行全体を排除する**。$O(n^2)$ が $O(n)$ に圧縮される。

```python
class Solution:
    def twoSum(self, numbers: list[int], target: int) -> list[int]:
        left, right = 0, len(numbers) - 1

        while left < right:
            current_sum = numbers[left] + numbers[right]

            if current_sum == target:
                return [left + 1, right + 1]
            elif current_sum < target:
                left += 1
            else:
                right -= 1

        return []
```

> 時間 $O(n)$ · 空間 $O(1)$

核心の洞察：**秩序が確定性を生む。** 配列がソート済みだから、「左に動かす」は常に「増大」を意味し、「右に動かす」は常に「減少」を意味する。その予測可能性が端点を安全に淘汰させる——もう一つの方向に希望がないことが*分かる*ので、残った一方だけが候補になる。

ソートがなければ、ハッシュマップと $O(n)$ 空間が必要——カオスな配列では、どの方向も安全に排除できない。排除できないから、全て覚えなければならない。

**🏢 職場**
めちゃくちゃな状況に足を踏み入れた時——入り組んだコードベース、乱雑なチーム、不明確な意思決定ツリー——本能はすぐに決定を始めることかもしれない。待て。**先に秩序を確立する。** 情報を整理する。何が増大し何が減少するかを理解する。依存関係を把握する。

状況が秩序化されたら——優先順位が揃い、制約が特定され、関係が明確化されたら——意思決定は推測でなくなる。現状を見て言える：*「小さすぎる、より大きな値に向かって動こう」* または *「多すぎる、より小さな値に向かって動こう。」* 各ステップが間違った手のクラス全体を排除する。

秩序を確立する前に戦略に飛びつくのは、ハッシュマップのやり方だ：動くが、コストは $O(n)$ メモリと $O(n^2)$ 比較だ。安全に忘れられる構造をまだ建てていないから、全てを頭に詰め込んでいる。

**🌍 人生**
**秩序を確立してから戦略を調整する方が、カオスの中で盲目的に選ぶより合理的だ。**

人生が圧倒的に感じる時——選択肢が多すぎ、義務が多すぎ、明確な優先順位がない——本能は最も近い選択肢を掴んで走ることだ。だがそれはソートされていない配列での総当たりだ。何もソートされていないから全ての選択が等しく妥当に見え、単調性がないから全ての方向が等しくもっともらしく見える。

成熟したやり方：まずソートする。重要度で選択肢を並べる。配列が秩序化されたら——優先事項が最も重要なものから最も重要でないものへ、体力が高いものから低いものへ、締め切りが近いものから遠いものへ——双対ポインタのアプローチが使えるようになる。両端を見て言える：*「この組み合わせは多すぎる、重い方を捨てよう」* または *「少なすぎる、より多い方に向かって動こう。」* 各意思決定が間違った分岐全体を排除する。

ソートは無駄な時間ではない。自信のある低コストな意思決定の前提条件だ。それがなければ、全ての選択はハッシュマップの検索——高価で、網羅的で、不安を引き起こす。それがあれば、全ての選択はポインタの移動——$O(1)$、 deliberate、安全。

**⚠️ アンチパターン**
*"とりあえず組み合わせを試してどうなるか見よう。"*
それはソートされていない配列での総当たりだ。どの方向も正解かもしれないから何も排除できず、全てを同時に頭に持つ——$O(n^2)$ の比較と $O(n)$ のメモリがかかる。ソートは $O(n \log n)$ の事前コストだが、下流の $O(n^2)$ を省く。「時間を節約する」ためにソートを飛ばすのは、問題解決において——そして人生において——最も高くつく虚偽の節約だ。
