### 13. Two Sum II

> *给定一个有序数组，找到两个数使其和等于目标值。*

**🧩 算法**
数组已经排好序了。这不是一个细节——这就是整个算法。

左指针放在最左（最小值），右指针放在最右（最大值）。算它们的和。只有三种情况：

- `sum == target` → 搞定。
- `sum < target` → 和太小。右指针左移只会让和更小（数值递减）。所以当前左指针和任何其他右端点的组合都太小。淘汰左指针，右移。
- `sum > target` → 和太大。左指针右移只会让和更大。所以当前右指针和任何其他左端点的组合都太大。淘汰右指针，左移。

每一步不只是检查一个组合——它**排除了一整行搜索空间**。$O(n^2)$ 压缩成 $O(n)$。

```python
class Solution:
    def twoSum(self, numbers: list[int], target: int) -> list[int]:
        left, right = 0, len(numbers) - 1

        while left < right:
            current_sum = numbers[left] + numbers[right]

            if current_sum == target:
                return [left + 1, right + 1]
            elif current_sum < target:
                left += 1
            else:
                right -= 1

        return []
```

> 时间 $O(n)$ · 空间 $O(1)$

核心洞察：**有序带来确定性。** 因为数组已排序，"左移"一定意味着"增大"，"右移"一定意味着"减小"。这种可预测性让你能安全地淘汰一个端点——你*知道*另一个方向没有希望，所以剩下的那个是唯一的候选。

没有排序，你就需要哈希表和 $O(n)$ 空间——因为在混沌的数组里，没有方向可以被安全淘汰。你不能排除，所以必须全部记住。

**🏢 职场**
当你走进一团乱的局面——纠缠不清的代码库、混乱的团队、不清晰的决策树——你的本能可能是立刻开始做决定。别急。**先建立秩序。** 整理信息。搞清楚什么在增大、什么在减小。理清依赖关系。

一旦局面被理清了——优先级排好、约束条件识别出来、关系厘清——你的决策就不再是猜。你可以看当前状态说：*"这个太小，朝更大的方向走"* 或者 *"这个太多，朝更小的方向走。"* 每一步排除一整类错误的选择。

在建立秩序之前就急着上策略，是哈希表的做法：能跑，但代价是 $O(n)$ 内存和 $O(n^2)$ 比较成本。你把一切都装在脑子里，因为你还没建出能让你安全遗忘的结构。

**🌍 人生**
**先建立秩序再调整战略，比在混沌里盲目选择要合理。**

当生活让人喘不过气——太多选项、太多义务、没有清晰的优先级——本能是抓住最近的选项就跑。但那是在无序数组上做暴力搜索。每个选择看起来都一样合理，因为什么都没排序；每个方向看起来都一样靠谱，因为不存在单调性。

成熟的做法：先排序。按重要性排列你的选项。一旦数组有序——优先级从最重要到最不重要、精力从最高到最低、截止日期从最近到最远——双指针方法就可用了。你可以看两端说：*"这个组合太多了，丢掉重的那一端"* 或 *"这个太少了，朝更多的方向走。"* 每个决策排除一整条错误的分支。

排序不是浪费时间。它是自信、低成本决策的前提。没有它，每个选择都是哈希表查询——昂贵、彻底、焦虑。有了它，每个选择是指针移动——$O(1)$、从容、安全。

**⚠️ 反模式**
*"先开始试组合看看哪个行。"* 那是无序数组的暴力法。代价是 $O(n^2)$ 次比较和 $O(n)$ 内存，因为你什么都排除不了——每个方向都可能是对的，所以你把一切都同时装在脑子里。排序花 $O(n \log n)$ 前期成本，但省下 $O(n^2)$ 的下游成本。为了"省时间"跳过排序，是解题中——也是人生中——最昂贵的虚假节约。
