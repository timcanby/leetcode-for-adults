### 16. Remove Duplicates from Sorted Array

> *ソート済み配列から重複を in-place で削除し、ユニーク要素数を返す。*

**🧩 アルゴリズム**
配列はソート済みだ。それは重複が常に隣り合っていることを意味する——「何を見たか」を覚える必要はなく、直前に保持したものと次のものを比較するだけでいい。ソートが全局の重複排除を局所的な比較に変える。

二つのポインタ、同じ方向：`read` は前方に走査し、`write` は最後に確定したユニーク要素を示す。`read` が `nums[write]` と異なる値を見つけるたび、それは新しいユニーク要素——`write` を進めて書き込む。重複がスキップされるのは「削除された」からではなく、有効領域に書き込まれないからだ。

ループ不変条件：`nums[0:write+1]` は常に、これまでに見た全ユニーク要素を元の順序で含む。前方はクリーンに保たれる。`write` より後はどうでもいい——それはスクラップの山で、何があるか誰も気にしない。

```python
class Solution:
    def removeDuplicates(self, nums: list[int]) -> int:
        if not nums:
            return 0

        write = 0

        for read in range(1, len(nums)):
            if nums[read] != nums[write]:
                write += 1
                nums[write] = nums[read]

        return write + 1
```

> 時間 $O(n)$ · 空間 $O(1)$

核心の洞察：**先にソートし、それから重複を排除する。** 配列がソートされていなかったら、ハッシュセットが必要——$O(n)$ の追加空間——なぜなら新しい要素は以前見たどれかの重複かもしれず、全て覚えていなければならないからだ。ソートが重複を隣接させ、問題を「これをどこかで見たことがあるか？」から「これは直前のものと同じか？」に——$O(1)$ で答えられる局所的な問いに——塌縮させる。

**🏢 職場**
めちゃくちゃな状態を引き継いだ時——膨張したコードベース、膨大なチーム構造、入り組んだ重複責任——本能は切り始めることだ：重複を削除し、冗長を統合し、散らかりを片付ける。

だが核心は：**カオスに重複排除はできない。** 何もソートされていなければ、どの要素も他の要素のコピーかもしれない。冗長を見つけるためにシステム全体を頭に持つ——精神的ハッシュセット——必要がある。それは $O(n)$ の脳空間と $O(n^2)$ の比較コストで、しかも見落としがある。

賢いやり方：**先にソートする。** 関連する作業をグループ化し、隣接する責任を整列させ、散らかりを似たものが隣り合うクラスタに配置する。システムがソートされたら——チーム別、ドメイン別、所有権別——重複は*隣接*しているから一目瞭然だ。問いは「組織のどこに重複があるか？」ではなく「これと今見たものは同じか？」になり——一瞥で答えられる。

ソートは時間の無駄ではない。重複排除を $O(n)$ ではなく 1 ステップ $O(1)$ にする前提条件だ。それがなければ、重複候補を見つけるたびに組織図全体を走査する。あれば、隣と比較して進むだけだ。

**🌍 人生**
**秩序あるものを先に整理し、それからカオスを片付ける。**

人生には両方がある——すでにリズムにある習慣、すでにレーンにある人間関係、すでに流れているルーチンといった整然とした部分と、膨張した to-do リスト、半完成のプロジェクト、重複し矛盾する約束といったカオスな部分。

本能はカオスに直接攻撃することだ：冗長な約束を剪定し、重複するプロジェクトを統合し、複製された義務を削除する。だがソートされていない人生に重複排除することは、全てを同時に頭に持つことを意味する——新しい項目ごとに以前の全てと照合する——なぜならカオスな人生では何もが何かの重複かもしれないからだ。

成熟したアプローチ：**先に秩序を確立する。** 約束をカテゴリ順に並べる。目標をドメイン順に並べる。人間関係を近さ順に並べる。似たものが隣接したら——重なる三つのボランティア約束、同じ目標に仕える二つのサイドプロジェクト、同じ精力を削ぐ五つの社交義務——重複は努力なしに見えるようになる。大監査はいらない；必要なのは項目をソートし、「これは隣のものと同じか？」が自ずと答えられるようにすることだ。

そしてより深い真実：**人生のすでに整然とした部分は修理する必要がない。** すでにリズムにある習慣、すでに機能する人間関係、すでに流れるルーチン——それらは `nums[0:write+1]` で、すでにクリーンだ。すでにソートされたものを再編成するために精力を浪費しない。カオスな部分をソートして冗長性を局所的に見えるようにするために精力を使え——それからユニークを前方に圧縮し、ノイズを後方に沈ませる。

**⚠️ アンチパターン**
*"全てを監査して冗長を見つける必要がある。"*
それはソートされていない配列に重複排除を走らせることだ。$O(n^2)$ の比較と $O(n)$ のメモリがかかる——システム全体を頭に持ち、各要素を以前の全てと照合し、それでも見落とす。先にソートせよ。似た項目が隣接すれば、冗長性は局所的な問い——「これは隣と同じか？」——になり、全局的なものではなくなる。ソートは $O(n \log n)$ の事前コストだが、重複排除をマラソンから街角の散歩に変える。カオスを先にソートせずに監査するのは、既に見えたはずのものを見つける最も高価なやり方だ。
