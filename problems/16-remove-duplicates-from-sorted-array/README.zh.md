### 16. Remove Duplicates from Sorted Array

> *从有序数组中原地删除重复元素，返回不同元素的个数。*

**🧩 算法**
数组已经有序。这意味着重复元素一定相邻——你不需要记住"以前见过什么"，只需要比较当前值和上一个保留的值。排序把全局去重变成了局部比较。

两个指针，同向：`read` 向前扫描，`write` 标记最后一个已确认的唯一元素。`read` 每发现一个和 `nums[write]` 不同的值，就是一个新的唯一元素——`write` 前进，写入。重复元素被跳过不是因为被"删除"，而是因为它们从没被写入有效区域。

循环不变量：`nums[0:write+1]` 始终包含到目前为止的所有唯一元素，顺序正确。前面保持干净。`write` 之后的都不重要——那是废料堆，没人在乎上面有什么。

```python
class Solution:
    def removeDuplicates(self, nums: list[int]) -> int:
        if not nums:
            return 0

        write = 0

        for read in range(1, len(nums)):
            if nums[read] != nums[write]:
                write += 1
                nums[write] = nums[read]

        return write + 1
```

> 时间 $O(n)$ · 空间 $O(1)$

核心洞察：**先排序，再去重。** 如果数组无序，你就需要哈希集——$O(n)$ 额外空间——因为任何新元素都可能是之前见过的任何一个的重复，你得把它们全部记住。排序让重复元素相邻，于是问题从"我在哪里见过这个吗？"塌缩成"这个和它前面那个一样吗？"——一个 $O(1)$ 就能回答的局部问题。

**🏢 职场**
当你接手一团乱——臃肿的代码库、庞大的团队结构、纠缠不清的重叠职责——本能是直接开始砍：删除重复，合并冗余，清理杂乱。

但关键是：**你不能对混沌去重。** 如果什么都没排序，每一项都可能是另一项的副本。你需要把整个系统装在脑子里——一个精神哈希集——才能发现冗余。那是 $O(n)$ 脑力空间和 $O(n^2)$ 比较成本，而且你还是会漏。

聪明的做法：**先排序。** 把相关的工作归组，相邻的职责对齐，把杂乱排列成相似的聚在一起。一旦系统被排序了——按团队、按领域、按归属——重复就变得显而易见，因为它们*相邻*。问题不再是"这在组织里哪里有重复？"而是"这和我刚看过的那个一样吗？"——一眼就能答。

排序不是浪费时间。它是让去重变成每步 $O(1)$ 而非 $O(n)$ 的前提。没有它，你每发现一个可能的重复就要扫描整个组织架构图。有了它，你跟邻居比一比就过去了。

**🌍 人生**
**先把有序的整理好，再整理杂乱。**

你的生活既有有序的部分——已经在节奏里的习惯、已经在各自轨道上的关系、已经流畅的日常——也有杂乱的部分—— sprawling 的待办清单、半成品的项目、重叠和重复和矛盾的承诺。

本能是直接攻击杂乱：修剪冗余的承诺，合并重叠的项目，删除重复的义务。但对一个无序的生活去重意味着把一切都同时装在脑子里——每来一个新事项就对照之前所有的——因为在杂乱的生活里，任何东西都可能是任何东西的重复。

成熟的做法：**先建立秩序。** 按类别排列你的承诺。按领域排列你的目标。按亲密度排列你的关系。一旦相似的东西相邻——三个重叠的志愿承诺、两个服务于同一目标的副业项目、五个消耗同一精力的社交义务——重复就毫不费力地浮现了。你不需要一次大审计；你需要的是把事项排好，让"这和旁边的那个一样吗？"自己回答自己。

这里有一个更深的真相：**生活中已经有序的部分不需要修理。** 已经在节奏里的习惯、已经有效的关系、已经流畅的日常——那些是 `nums[0:write+1]`，已经是干净的了。别浪费精力重新组织已经排好的。把精力花在把杂乱部分排序上，让它的冗余变成局部可见——然后把唯一的压实到前面，让噪声沉到后面。

**⚠️ 反模式**
*"我需要审计一切来找出冗余。"* 那是对无序数组做去重。成本是 $O(n^2)$ 次比较和 $O(n)$ 内存——你把整个系统装在脑子里，每项对照之前所有的，还是会漏。先排序。一旦相似项相邻，冗余就变成局部问题——"这和它邻居一样吗？"——而不是全局问题。排序花 $O(n \log n)$ 前期成本，但把去重从马拉松变成绕街区散步。不对混沌先排序就审计，是发现你本可以看到的东西的最贵方式。
