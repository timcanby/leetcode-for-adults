### 17. Linked List Cycle

> *判断一个链表是否有环——不存储每个访问过的节点。*

**🧩 算法**
最直觉的做法：把每个访问过的节点记进哈希集合。如果同一个节点出现两次，就有环。能用，$O(n)$ 时间——但需要 $O(n)$ 空间，因为你把整个历史都装在内存里了。

Floyd 的做法：放进两个指针，一个每轮走 1 步，另一个走 2 步。如果没有环，快指针先冲出链表。如果有环——两个指针都进入环——这就是一个有限跑道上的追及问题。快指针每轮多走 1 步。在有限的 $m$ 个位置上，每轮多 1 步，保证最多 $m$ 轮就追上。不是"可能"——是"一定"。

```python
class Solution:
    def hasCycle(self, head) -> bool:
        slow = fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            if slow is fast:
                return True

        return False
```

> 时间 $O(n)$ · 空间 $O(1)$

核心洞察：**检测环不需要记住过去。** 两个以不同速度运动的东西在闭合轨道上*一定*会相遇——不是因为运气好，而是因为相对速度恒定、轨道有限。"我以前来过这里吗"的记忆被"两个东西在环上追逐，快的一定追上"的物理替代了。

哈希集做法问的是：*"我留记录了吗？"* Floyd 问的是：*"动力学是否保证碰撞？"* 一个需要记忆，另一个只需要数学。

**🏢 职场**
你知道这个模式：每个周一都在修上周五崩的东西。同样的故障、同样的冲突、同样的沟通失误。你不是在解决问题——你在走环。

最直觉的做法：给每个遇到的问题建一个日志，新问题来就和历史对照。这是哈希集——$O(n)$ 脑力空间，而且你得一直维护它。能用，但累人：你把整个事故档案都扛在脑子里。

Floyd 的做法：**别记录了。看动力学。** 如果同样的两个团队一直在碰撞，如果同样的升级路径在反复出现，如果同样的瓶颈每个 sprint 都重现——你不需要一个全面审计来证明这是环。你需要两个以不同速度运动的东西：快的那一个（很快升级的人）和慢的那一个（慢慢推进的流程）。如果它们反复在同一个点相遇，那就是证明。

环不是被穷举记忆检测到的。它被运动的*形状*检测到——没有进展的重复。两个速度在有限轨道上，反复相遇。那就是环，而解法不是把日志记得更详细。解法是**断开那条边**——改变结构，让环不再存在。

**🌍 人生**
哈希集做法的人生版本：记录每次冲突、每次争吵、每个重复的模式。建一份完整的"以前发生过的事"的档案，好在再次发生时认出来。能用。但代价是你把每段关系的全部情感历史都扛在脑子里——$O(n)$ 空间，永远。

Floyd 的做法：**检测环不需要记住每次争吵。你需要看动力学。**

这里的洞察是：**重复不需要记忆来证明——它需要不同的速度。** 让两个东西运动：你的反应（快）和底层模式（慢）。如果你的反应反复到达和模式相同的地方——同样的争吵、同样的怨恨、同样的退缩——你就在环里。不是因为你编目了历史，而是因为动力学让它不可避免。

这里有一个更深的真相：**在环里，走更快没用。** 快指针不是因为快就逃出环——它只是套了慢指针一圈。在环里更努力、反应更快、投入更多强度——都不会断开环。快指针和慢指针相遇，*因为*轨道是闭合的，不是因为它慢。

唯一的出路是**断开那条边**——改变结构，让环不再存在。可能是一次新的对话、一条新的边界、一个新流程，或者直接离开这条轨道。在环里，每往前一步都是绕环再走一步。出口不是一个步骤——是一个结构改变。

**⚠️ 反模式**
*"下次我记录更详细一点。"* 那是哈希集做法：$O(n)$ 记忆靠暴力回忆来检测环。能用，但这是你永远要付的税——你在维护一个不断增长的档案，记录每次冲突、每个模式、每件"以前发生过的事"。Floyd 告诉你：你不需要这个档案。你需要的是动力学。如果生活中的两件事反复在同一点相遇，那*就是*证明——不需要日志。花精力做更好的记录而不是断开环，是最昂贵的否认形式：看起来像勤奋，实际只是在闭合轨道上走得更快。
