### 19. Sliding Window

> *重複なしの最長部分文字列（#3）。必要な全文字をカバーする最短部分文字列（#76）。*

**🧩 アルゴリズム**
スライド窓は連続区間 `[left, right]` で、データに沿って前にスライドする。二つのポインタは対向ではない——**協力**する：`right` は拡張し、`left` は修復する。right は新領域に踏み込む。left は窓が壊れた時に収縮する。

二つのフレーバーがあり、その違いが全体の洞察だ：

**最長の合法窓（#3）：** 窓が非合法になるまで `right` を拡張（重複が出現）。それから再び合法になるまで `left` を収縮。修復*の後*に答を更新。マントラ：**貪欲に拡張し、壊れたら縮める。**

```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        seen = set()
        left = 0
        ans = 0

        for right in range(len(s)):
            while s[right] in seen:
                seen.remove(s[left])
                left += 1
            seen.add(s[right])
            ans = max(ans, right - left + 1)

        return ans
```

**最短の充足窓（#76）：** 窓が要件を*満たす*まで `right` を拡張（全文字カバー）。それからまだ合法の間に貪欲に `left` を収縮し、最もきついフィットを見つける。収縮*中*に答を更新。マントラ：**満たすまで拡張し、それから絞る。**

```python
from collections import Counter, defaultdict

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = Counter(t)
        window = defaultdict(int)
        left = 0
        valid = 0
        start = 0
        min_len = float("inf")

        for right, ch in enumerate(s):
            if ch in need:
                window[ch] += 1
                if window[ch] == need[ch]:
                    valid += 1

            while valid == len(need):
                if right - left + 1 < min_len:
                    min_len = right - left + 1
                    start = left

                if s[left] in need:
                    if window[s[left]] == need[s[left]]:
                        valid -= 1
                    window[s[left]] -= 1
                left += 1

        return s[start:start + min_len] if min_len != float("inf") else ""
```

> 時間 $O(n)$——`left` と `right` は各々最大 $n$ 歩右に歩く · 空間 $O(k)$、$k$ = 文字セットサイズ

より深い原理：**right は未知に拡張し、left は既知を修復する。** right は探検者——常に前進し、振り返らず、常に新しい領域を追加する。left は修理工——何かが壊れた時にのみ動き、しかも削るだけで、決して追加しない。彼らは調整せずに協力する：right は left を待たず、left は right を予測しない。窓の合法性が彼らを繋ぐ不変条件だ——right はそれを壊すかもしれず、left はそれを復元しなければならず、答は不変条件が成立している時のみ安全に更新できる。

**🏢 職場**
プロジェクトはスライド窓だ。`right` は成長するスコープ——毎スプリント届く新機能、新要件、新ステークホルダー。`left` はクリーンアップ——レガシーコードの非推奨化、古いドキュメントの削除、旧システムのサンセット。

二つのフレーバーが直接対応する：

**最長窓（#3）：** 最大スコープが欲しい——より多くの機能、より多くのカバレッジ、より多くの成果。貪欲に拡張する。だが新追加がコンフリクトを作ったら（二つのチームが同じドメインを所有、二つの機能が重複）、*直ちに収縮*してコンフリクトを排除。壊れたまま拡張し続けない。重複を修正してから続ける。答——最大の有効スコープ——は窓がクリーンな時のみ有効だ。

**最短窓（#76）：** 最小コストが欲しい——全要件を*カバーしつつ*最も小さいチーム、最もタイトな予算、最もリーンなプロセス。全要件が満たされるまで拡張し、それから*絞る*——まだ全てをカバーしている間に、左からトリム：冗長な会議を削り、重なる責任を切り、最初の二つの承認が既にカバーしている三つ目の承認を落とす。答——最小の実行可能プロセス——は*絞り中*に見つかり、拡張の後にではない。

そして規律は：**right は決して振り返らない。** right は既に走査した領域に再訪しない。left もそう。両ポインタは前方にのみ歩く。実践では：ステークホルダー、機能、プロセスのステップを一度追加したら、「元に戻す」のではなく——left に古いものを削除させ、right に新しいものを推進させる。バックトラックなし。窓は一方向にスライドし、決して反転しない。

**🌍 人生**
あなたの注意はスライド窓だ。`right` は新しいもの——新しい興味、新しい義務、人生に入ってきた新しい人。`left` は手放すもの——もう役に立たない古い約束、もう合わない古い習慣、ずっと我慢してきた精力の消耗。

**最長窓（#3）：** 最も長く邪魔されない集中が欲しい。`right` を拡張——新しい体験を入れ、新しい挑戦を受け入れる。だがコンフリクトが現れたら——重複する約束、反復する義務、フローを壊すもの——*直ちに `left` を収縮*。コンフリクトを作っている古いものを捨てる。人生の重複を我慢するな。最も長く途切れない集中は、貪欲な拡張と即時の修復から来る。

**最短窓（#76）：** 重要な全てをカバーしつつ最もリーンな人生が欲しい。全ニーズが満たされるまで拡張——健康、人間関係、仕事、意味。それから*絞る*——まだ全てをカバーしている間に、余分をトリム：もう価値を加えない社交義務、罪悪感から維持している趣味、他の三つと重なる約束。答——最小の実行可能な人生——は永遠に拡張して見つかるのではない。満たされるまで拡張し、きつくなるまで絞って見つかる。

そして普遍の原理：**right は決して振り返らない。** 既に通過した領域に再訪しない。自分の古いバージョンに「戻る」ことはしない。`right` は新しいものに前進し、`left` は古いものを落とす。人生の窓は一方向にスライドする——前方へ——そして芸術は、いつ拡張し、いつ収縮するかを知ることであり、いつ反転するかではない。

人生のための二つのマントラ：
- **最長フロー：** 壊れるまで拡張し、直るまで縮める。重複を我慢するな。
- **最リーン人生：** 十分になるまで拡張し、きつくなるまで絞る。冗長を背負うな。

**⚠️ アンチパターン**
*"窓にもう一つ追加しよう——たぶん大丈夫だろう。"*
それは `right` を拡張するだけで `left` を決して収縮させないことだ。窓は壊れるまで成長し——そして成長し続ける。修復しないからだ。最長窓の問題は壊れたら縮めることを要求し、最短窓の問題は満たされたら絞ることを要求する。拡張だけで収縮しなければ、最長の合法窓も最短の充足窓も得られない——何も満たさず何も最大化しない、溢れた、膨張した、非合法な窓を得るだけだ。規律は拡張にあるのではなく、収縮にある。right は簡単だ——ただ「もっと追加」だから。left こそが芸術だ——何を、いつ落とすかを知ること。
