### 20. Find All Anagrams in a String

> *s の中で p のアナグラムとなる部分文字列の開始位置を全て見つける。*

**🧩 アルゴリズム**
アナグラムとは：同じ文字、同じ個数、異なる順序。つまり*内容*をマッチするのではなく——*頻度*をマッチする。窓は最適を求めて拡張・収縮するのではなく——**固定サイズ**で、正確に `len(p)` の幅で `s` に沿ってスライドする。

各ステップ：`right` が一つ進み、一文字追加。窓が `len(p)` を超えたら、`left` が一つ進み、最も古い文字を削除。窓は常に正確に `len(p)` の幅——文字列に沿ってスライドする固定のフレーム。

各位置で、窓の文字頻度と `p` の頻度を比較。一致したら——同じ文字、同じ個数——それはアナグラム。開始インデックスを記録。

```python
from collections import Counter

class Solution:
    def findAnagrams(self, s: str, p: str) -> list[int]:
        need = Counter(p)
        window = Counter()
        ans = []
        left = 0

        for right, ch in enumerate(s):
            window[ch] += 1

            if right - left + 1 > len(p):
                window[s[left]] -= 1
                if window[s[left]] == 0:
                    del window[s[left]]
                left += 1

            if right - left + 1 == len(p) and window == need:
                ans.append(left)

        return ans
```

> 時間 $O(n \cdot k)$、$k$ = 文字セットサイズ · 空間 $O(k)$

より深い原理：**フレームサイズが固定の時、唯一の問いは今フレームの中にあるものは何か、だ。** 長さを最適化しているのではない——各位置で同一性をチェックしている。窓は伸縮しない；スライドする。そして各停止で一つの問いを尋ねる：*「今見ているものは探しているものと一致するか？」* 「調整すれば一致するか？」ではなく——「一致するか、はいまたはいいえ？」

**🏢 職場**
ある問題は最適化についてではない——**固定位置でのパターンマッチング**についてだ。テンプレートがある：ジョブスペック、プロジェクトチェックリスト、チーム構成要件。そして候補のストリームがある——履歴書、プロジェクト、チーム構成——が目の前を流れる。仕事は最長や最短のフィットを探すことではない。固定サイズのフレームをストリームに沿ってスライドさせ、各位置で尋ねることだ：*「これはスペックに合うか？」*

間違いはフレームを伸縮させようとすることだ。「この候補は 5 つの要件の 4 つを満たすから、要件を広げよう……」——いや。スペックはスペックだ。窓は `len(p)` の幅だ。スライドし、チェックし、進む。現在の位置が合わなくても、フレームを交渉するな——次の位置に進め。

アナグラムの洞察はより鋭い：**内容の一致 ≠ 順序の一致。** 正しい候補はスキルを「正しい順序」で並べないかもしれない——履歴書が期待と違って見えるかもしれない、プロジェクトが好む順序に従わないかもしれない——だが*能力のセット*が一致すれば、それはアナグラムだ。順序が違うからと言って一致を拒絶するな。頻度が重要で、配置ではない。

**🌍 人生**
人生のスライド窓の多くは可変サイズだ——フレームを伸縮して最長や最短を見つける。だがある状況は**固定フレーム**を与える：正確に 3 年の経験を必要とする仕事、正確に 12 ヶ月の賃貸、正確に $5,000 の予算、正確に 2 週間の締め切り。フレームは伸縮しない。選択肢に沿ってスライドし、各位置で尋ねる：*「今このフレームの中にあるものは、私の必要とするものに一致するか？」*

ここでの洞察：**フレームが固定の時、フレームサイズを変えようとするな。** 制約が rigid の時——予算 $5,000、タイムライン 2 週間、チーム 3 人——制約を交渉するために精力を浪費するな。選択肢に沿ってスライドし、各々をスペックに対してチェックし、全ての一致を集める。ある位置は一致する；大半はしない。それでいい。目標は全ての位置を一致させることではなく——**一致する全ての位置を見つけること**だ。

そしてアナグラムの知恵：**正しい人生はあなたが描いた人生のように見えないかもしれない——だが構成要素が一致すれば、それがフィットだ。** 想像したもの：都市の仕事、ダウンタウンのアパート、子供 2 人、犬。見つけたもの：リモートの仕事、郊外の一戸建て、子供 2 人、猫。異なる順序、異なる配置——だが頻度は一致する。同じ文字、同じ個数、異なるシーケンス。期待した順序と一致しないからと言って拒絶するな。それはあなたが望んだ人生のアナグラムだ。

**⚠️ アンチパターン**
*"窓のサイズを調整して一致を見つけられるか試そう。"*
それは固定窓の問題を可変窓の問題として扱うことだ。窓は `len(p)` ——伸縮しない。現在の位置が一致しなくても、答えはフレームをリサイズすることではなく、前にスライドすることだ。固定フレームをリサイズして一致を強制するのは、候補に合わせてジョブスペックを書き直すようなものだ：「一致」を見つけるが、探していた一致ではない。スペックがフレームを定義する。データにスペックを再定義させるな。スライドし、チェックし、一致を記録し、進む——フレームは固定のままで、見つけた全てのアナグラムは本物だ。
