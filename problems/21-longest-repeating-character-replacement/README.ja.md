### 21. Longest Repeating Character Replacement

> *最大 k 個の文字を置換して全て同じ文字にできる最長の部分文字列を見つける。*

**🧩 アルゴリズム**
既に合法な窓を探しているのではない。窓を*合法にできる*かを探している——「合法」とは「全て一文字で、置換は最大 k 回」。

核心の洞察：窓 `[left, right]` が全て同じ文字にできるのは、`(窓の長さ) - (窓内で最も頻出する文字の頻度) ≤ k` の時のみ。「無駄」は主導文字以外の全て。無駄が `k` の置換予算に収まれば、窓は実行可能だ。

だから：`right` を拡張し、文字を追加。`max_freq`——現在の窓で最も頻出する文字のカウント——を追跡。`(right - left + 1) - max_freq > k` の時、窓の無駄が多すぎる。無駄が `k` に戻るまで `left` を収縮。

```python
from collections import defaultdict

class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = defaultdict(int)
        left = 0
        max_freq = 0
        ans = 0

        for right, ch in enumerate(s):
            count[ch] += 1
            max_freq = max(max_freq, count[ch])

            while (right - left + 1) - max_freq > k:
                count[s[left]] -= 1
                left += 1

            ans = max(ans, right - left + 1)

        return ans
```

> 時間 $O(n)$ · 空間 $O(k)$、$k$ = 文字セットサイズ

より深い原理：**全てを同じにする必要はない——違いが予算に収まる必要がある。** 主導文字は賭けるもの。`max_freq` は錨——既に機能しているもの。他は全てノイズ。問いは「この窓は完璧か？」ではなく「ノイズは吸収できるほど小さいか？」だ。

そしてここに微妙な美しさがある：**`max_freq` は増えるだけで減らない。** `left` が動いても下げない、必要ないからだ。より高い `max_freq` はより厳しい制約を意味する——だが最も長い窓を探しているので、より厳しい制約は現在の答に*より確信*を持たせるだけで、減らさない。窓は既に見つけたものより小さくなる必要はない。`ans` は増えるのみ。`max_freq` は増えるのみ。アルゴリズムは単調だ——前に進み、決して退かない。

**🏢 職場**
完璧なチームはいらない。**ノイズが予算に収まる**チームが要る。

`max_freq` は最強の貢献者——コアの負荷を担う人、チームを錨で固定するスキル、既に機能するプロセス。他は全て分散：指導が必要なジュニア、時々壊れるツール、追加コミュニケーションが必要なステークホルダー。

`k` はマネジメント予算：コーチング能力、技術的負債の許容度、摩擦への忍耐。窓——チームの有効スコープ——は `(総スコープ) - (錨が既に処理するもの) ≤ k` の時に合法。ノイズが予算を超えたら、錨を解雇しない。スコープを縮める——サイドプロジェクトを切り、会議負荷を減らし、スプリントを狭める——分散が吸収できる範囲に収まるまで。

そして単調な洞察：**最強の貢献者の最高のストリークは上がるだけだ。** 事態が乱れても `max_freq` を下げない。ピークを覚えておく——最良の人がスプリント全体を背負った時——それを錨に使う。より低い錨は早すぎる収縮を招く。ピークの記憶が拡張し続けさせる。

**🌍 人生**
完璧な人生はいらない。**欲しいものとの違いが許容範囲に収まる**人生が要る。

`max_freq` は主導する糸——人生で最も多くの空間を占め、既に機能している人、習慣、価値、活動。他は全て分散：運動しない日、不健康な食事、深くない会話。`k` は自分への同情予算——自分に許す余裕、許容する不完全、受け入れる「十分」。

人生の窓は `(している全て) - (既に整ったもの) ≤ k` の時に合法。ノイズ——整わない習慣、精力の消耗、コアに合わない約束——が許容を超えたら、錨を放棄しない。窓を縮める：合わない約束を切り、精力の消耗を手放し、スコープを狭める——分散が吸収できる人生に収まるまで。

そしてここに解放的な洞察がある：**`max_freq` は増えるだけだ。** 悪い週があっても最高の自分を下げない。ピークを覚えておく——毎朝走り、毎晩読み、全ての友人に現れた自分のバージョン——それを錨に使う。より低い錨は窓を早すぎるほど縮める。ピークの記憶が拡張し続けさせ、手を伸ばし続けさせ、窓を成長し続けさせる。

最長の合法な人生はノイズゼロの人生ではない。ノイズが `k` に収まる人生——自分が何かと何が欲しいかの違いが吸収できるほど小さい人生だ。完璧を要求するな。分散が予算に収まることを要求する。それから拡張する。

**⚠️ アンチパターン**
*"全てを直してから拡張する必要がある。"* それは `k = 0` ——ノイズへのゼロ許容、分散へのゼロ予算。窓は `max_freq` そのものに縮む——主導文字だけで、他には何もない。プロジェクトも人生もチームも、単一の文字の反復ではない。`k` の全ての意味は**あるノイズは吸収可能**ということ——予算は貯めるためにあるのではなく、使うためにある。全てが整うまで拡張を拒めば、決して拡張しない。最長の窓は置換ゼロの窓ではなく、置換がちょうど収まる窓だ。予算を使え。拡張しろ。ノイズが本当に溢れた時にのみ収縮する。
