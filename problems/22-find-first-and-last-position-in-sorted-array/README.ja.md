### 22. Find First and Last Position in Sorted Array

> *ソート済み配列でターゲット値の開始・終了インデックスを見つける。存在しない場合は [-1, -1] を返す。*

**🧩 アルゴリズム**
*ある*ターゲットを探しているのではない——ターゲットの範囲の**境界**を探している。配列はソート済みなので、target の全出現は連続している。問いは「target は存在するか？」ではなく——「target はどこから*始まり*、どこで*終わる*か？」だ。

二つの二分探索：
- `lower_bound(target)` → 最初の `nums[mid] >= target` のインデックス。これが**左境界**——target の範囲が始まる場所。
- `lower_bound(target + 1) - 1` → 最後の `nums[mid] < target + 1` のインデックス。これが**右境界**——target の範囲が終わる場所。

```python
class Solution:
    def searchRange(self, nums: list[int], target: int) -> list[int]:
        def lower_bound(x):
            left, right = 0, len(nums)

            while left < right:
                mid = left + (right - left) // 2

                if nums[mid] < x:
                    left = mid + 1
                else:
                    right = mid

            return left

        left_idx = lower_bound(target)

        if left_idx == len(nums) or nums[left_idx] != target:
            return [-1, -1]

        right_idx = lower_bound(target + 1) - 1

        return [left_idx, right_idx]
```

> 時間 $O(\log n)$ · 空間 $O(1)$

より深い原理：**境界を見つけることは値を見つけることと同じではない。** target を検索してインデックス 5 で見つけられる——だがそれは範囲が `[5, 5]` か `[3, 12]` かを教えない。*一つの*出現を見つけるのは「存在するか？」に答える。*境界*を見つけるのは「どこまで伸びるか？」に答える。

鍵は `lower_bound` が*値*ではなく*閾値*を見つけることだ。`lower_bound(target)` は「target はどこか」ではなく「配列が最初に ≥ target になるのはどこか」を見つける。その閾値が左境界。そして `lower_bound(target + 1)` は「配列が最初に ≥ target+1 になるのはどこか」——target の範囲の直後の位置——を見つける。一つ引けば右境界だ。

尋ねているのは「*これは target か？*」ではなく——*「これは target の領土が始まり終わる境界か？」*だ。領土は閾値で定義され、個別のヒットで定義されるのではない。

**🏢 職場**
会社に入る時、自分のスキルを使う*ある*プロジェクトを見つける必要はない。自分のスキルが適用される**領土の境界**を見つける必要がある。

一つの出現——一つのプロジェクト、一つのチーム、一つのタスク——を見つけるのは安心するが誤解を招く。「スキルはここで使われる」と教えるが、それが一回きりの割り当てか三年の任期かを教えない。領土がどこで始まりどこで終わるかを教えない。

`lower_bound` のアプローチ：*閾値*を見つける——自分のスキルレベルが関連し始める最初のプロジェクト。それが左境界。次に、自分のスキルが*もはや*決定要因ではなくなる場所——次のティアの課題が始まる場所、senior+ の専門性が引き継ぐ場所——を見つける。それが右境界。その間の領土が活動範囲だ。

そしてキャリアの洞察：**左境界と右境界が同じなら——`lower_bound(target) == lower_bound(target + 1)` なら——target は配列に存在しない。** 閾値は見つけたが領土はない。会社は*理論上*自分のスキルレベルを必要とするが、どの役割もそれを*使って*いない。それがキャリアの `[-1, -1]` だ：スキルは名目上必要とされるが範囲は空。一つのヒットではなく境界を知ることで——本当に必要とされているか、ただ技術的に適格なだけか——が分かる。

**🌍 人生**
*ある*幸福の瞬間を見つける必要はない。**範囲**——幸福が持続可能な条件——を見つける必要がある。

一つの良い日——一つのフロー、一つの本物の会話——を見つけるのは単一のヒットだ。「幸福は可能だ」と教える。だがそれが一回きりか反復するパターンかを教えない。幸福の領土がどこで*始まり*どこで*終わる*かを教えない。

人生の `lower_bound` アプローチ：*閾値*を見つける——幸福が始まる最初の条件。多分：「一晩に 7 時間以上寝て、週に一人親しい友人に会う時。」それが左境界。次にそれが終わる場所——幸福がもはや安定しない条件、次のティアのストレスが始まる場所——を見つける。多分：「週に 2 以上のコミットメントを引き受ける時。」それが右境界。

その間の領土が幸福の範囲だ。一つのピークを追うのではなく——幸福が持続可能な**条件のバンド**だ。単一のヒットを探しているのではない——ヒットが*保証される*範囲の境界を探している。

そして人生の洞察：**左境界と右境界が同じなら——幸福の条件が狭すぎて範囲が空なら——target は配列に存在しない。** 閾値は見つけた（幸福は*可能*）が領土はない（幸福は*持続可能*ではない）。それが人生の `[-1, -1]` だ：理論上は達成可能だが実践上は到達不能。解決策は単一のヒットをより懸命に追うことではない。解決策は**範囲を広げること**——閾値を下げ、条件を緩め、幸福が生きる領土を拡大し——境界間が十分に広くなり、その間に人生が収まるようにすることだ。

**⚠️ アンチパターン**
*「一つのインスタンスを見つけた——それが存在することの証明だ。」* インデックス 5 で一つの出現を見つけるのは、target が*存在する*ことを教える。範囲が `[5, 12]` か `[5, 5]` か、5 が偶然ではないかを教えない。単一のヒットは「存在するか？」——間違った問い——に答える。正しい問いは「どこから*始まり*、どこで*終わる*か？」——境界であり、中間ではない。境界を見つけるのは一つのヒットと同じ $O(\log n)$——二分探索が一つではなく二つ——だが、領土の*形*を教える。単に「空ではない」ではなく。そして形——境界、範囲、事がどこから始まりどこで終わるか——を知ることが、その領土に住む価値があるかを判断する根拠となる。
