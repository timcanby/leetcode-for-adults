### 23. Bubble Sort

> *反复比较相邻对并交换到有序。每轮把最大的未排序元素"冒泡"到正确位置。*

**🧩 算法**
冒泡排序是计算机科学里最受嘲笑的算法——$O(n^2)$、幼稚、你第一个学然后立刻学会永远别用的东西。但它的机制藏着一个 quicksort 没有的教训。

每一轮：从左到右走。比较每对邻居。如果顺序错了，交换。一整轮之后，最大的元素已经"冒泡"到了末尾——它在它的最终位置了。下一轮少处理一个元素。重复，直到某一轮没有任何交换——意味着一切已经有序。

```python
def bubble_sort(nums):
    n = len(nums)

    for end in range(n - 1, 0, -1):
        swapped = False

        for i in range(end):
            if nums[i] > nums[i + 1]:
                nums[i], nums[i + 1] = nums[i + 1], nums[i]
                swapped = True

        if not swapped:
            break

    return nums
```

> 时间 $O(n^2)$ 最坏，$O(n)$ 最好（已排序）· 空间 $O(1)$

更深的原理：**最大的问题最先浮现。** 每轮把最大的未排序元素推到末尾——最不协调的东西最先暴露和修正。你不用去猎问题；你走一遍序列，大的那些会自己跟邻居碰撞而暴露。

而 `swapped` 标志是秘密智慧：**如果一整轮没有发生任何交换，你就完成了。** 你不需要提前知道你已经完成了。你只需要不断走，而摩擦的消失*就是*秩序已达成的信号。有序状态不是靠检查每个元素来检测的——而是靠观察摩擦停了来检测的。

**🏢 职场**
最大的组织问题最先浮现。你不需要一个大审计来找它们——你走一遍团队，逐人比较相邻的关系。哪里有摩擦——一对顺序错了、一个角色比邻居大——那里就是最大的未排序元素所在。交换它们：调整汇报结构、厘清责任边界、调动超载的人。

每一轮之后，最大的错位已经冒泡到它的最终位置——安定、有序、不再和邻居摩擦。然后你再走一轮，下一个最大的错位浮现。

而 `swapped` 标志是领导力洞察：**如果对组织走一整轮没有产生任何冲突，你已经有序了。** 你不需要检查每份报告、每个指标、每个流程。如果一次完整走查什么都没发现——没有摩擦、没有错位、没有需要交换的对——组织是稳定的。摩擦的消失*就是*证明。别审计了。别优化了。你完成了——直到下一次重组引入新的未排序元素。

陷阱在于冒泡排序是 $O(n^2)$——每轮很贵，你可能需要 $n$ 轮。在组织里，这意味着：别每周重组整个公司。但也别完全跳过走查。健康的模式：定期走一遍团队，让最大的冲突浮现，解决它们，在一轮没有摩擦时停下。一个这样做——定期走、小交换、早停——的组织，比每两年搞一次大重组或者从不检查的组织更健康。

**🌍 人生**
你人生最大的问题最先浮现——如果你让它们的话。你不需要去猎它们。逐日走一遍你的人生，比较相邻的时刻：昨天 vs 今天、这周 vs 上周、这个承诺 vs 下一个。哪里有摩擦——一段关系顺序错了、一个习惯比它的槽位大、一个承诺在挤压它的邻居——那里就是最大的未排序元素所在。

人生版的冒泡排序：**别试图一次性修好一切。先修最大的摩擦，让它安定，再走一轮。** 每轮把最大的错位移到正确位置。然后下一个最大的浮现。你不会先解决小问题——你会先解决大的，因为大的才是跟邻居碰撞、产生可见摩擦的那些。

而 `swapped` 标志是人生智慧：**如果对人生走一整轮没有产生摩擦，你已经有序了。** 你不需要记每个细节的日记、审计每个习惯、优化每个小时。如果对你一周的完整走查什么都没发现——没有关系在紧张、没有习惯在溢出、没有承诺在挤压邻居——你的人生是稳定的。摩擦的消失*就是*证明。别优化了。别为不存在的问题写日记了。去过生活。

纪律在于知道冒泡排序不是关于效率——而是关于**诚实**。它是拒绝假装的算法。它走真实的序列、看真实的邻居、只真正错位时才行动。没有巧妙的分区、没有分治、没有跳过。就是：走一遍、看一眼、修一下、摩擦停了就停。那不是排序数组最快的方式。但它可能是排序人生最诚实的方式。

**⚠️ 反模式**
*"我先修小事，大事会自己理顺。"* 那是插入排序，不是冒泡排序——而且反了。小事*不会*修好大事；大事会一直跟邻居碰撞、产生摩擦，直到你直接处理它们。冒泡排序有效，因为最大的未排序元素*必须*浮现——它藏不住，因为它比周围一切都大，不断挤压邻居，直到到达它的层级。小问题可以无限期地隐藏；大问题不行。先修最大的摩擦，让它安定，重复。小问题要么在这个过程中自己解决，要么在足够大到产生摩擦时浮现。别从下往上排——从上往下排，让小事找到自己的层级。
