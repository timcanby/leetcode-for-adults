### 26. Merge Sort

> *配列を半分に切り、各半分をソートし、二つのソート済み半分を合わせて戻す。*

**🧩 アルゴリズム**
マージソートは走査でも交換でも挿入でも選択でもソートしない。**分割統治**でソートする：問題を半分に切り、各半分を独立に解き、結果を縫い合わせる。そして*再帰的に*行う——各半分は四半分に、各四半分は八半分に——ピースが自明に小さくなるまで（一要素、既にソート済み）。それから鎖を上にマージし、二つのソート済み半分ずつで、配列全体が一つのソート済み全体になるまで。

```python
def merge_sort(nums):
    if len(nums) <= 1:
        return nums

    mid = len(nums) // 2
    left = merge_sort(nums[:mid])
    right = merge_sort(nums[mid:])

    ans = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            ans.append(left[i])
            i += 1
        else:
            ans.append(right[j])
            j += 1

    ans.extend(left[i:])
    ans.extend(right[j:])
    return ans
```

> 時間 $O(n \log n)$——常に、保証付き · 空間 $O(n)$

より深い原理：**大きな問題はまだ半分に切っていない小さな問題にすぎない。**

鋭さは再帰——*自己相似性*——にある。関数は同じ問題のより小さい版で自身を呼ぶ。百万の要素のソートの仕方を知る必要はない。二つの要素のソート（自明：比較して整序）と二つのソート済みリストのマージ（両方を歩き、小さい方を取る）を知るだけでいい。それだけ。切る → 再帰 → マージ。百万のソートは $\log_2(n)$ レベルの半分化で自ずと解ける。

そして保証：**マージソートの $O(n \log n)$ は典型的なだけでなく最悪ケースだ。** クイックソートが悪い入力で $O(n^2)$ に劣化するのとは異なり、マージソートの性能は*構造によって保証される*。各レベルが $O(n)$ の仕事をする。ちょうど $\log_2(n)$ レベルある。入力は何も壊せない。コストはサイズで決まり、配置ではない。カオスは課税しない。保証は構造から来る——毎回半分に切り、毎回線形でマージする——そして構造は嘘をつかない。

トレードオフ：**マージソートは $O(n \log n)$ の保証のために $O(n)$ の空間を払う。** マージ結果を保持するバッファが必要だ。配列内で入れ替えるインプレースソートとは異なり、マージソートはコピーして組み合わせる。保証にはメモリがかかる。入力に驚かされないという確実性の代償を払う。

**🏢 職場**
最大のプロジェクトは一人の机で一人で解決されない。**分割統治**で解決される：プロジェクトを半分に切り、各半分を独立に処理できるチームに渡し、結果をマージする。

マージソートの知恵：**問題全体の解き方を知る必要はない。切り方と、解のマージの仕方を知る必要がある。** 一つの問題を二つの独立したサブ問題に切り、二つのソート済みの解を一つの首尾一貫した答えにマージできれば、問題のサイズは関係ない——再帰のレベルが一つ増えるだけだ。

そして保証：**構造の良いチームの性能は、プロジェクトの難易度に関わらず $O(n \log n)$ だ。** 組織の各レベルが仕事を切り結果をマージできれば、総コストは内容ではなく構造で決まる。難しいプロジェクトはより多くのレベルを必要とするが（より深い再帰）、各レベルは同じ種類の仕事をする：切る、解く、マージ。切りがクリーンでマージが有能なら、どんなプロジェクトも——どんなにカオスでも——構造を $O(n^2)$ に劣化させない。構造がカオスから守る。

だがトレードオフ：**マージソートは保証のために空間を払う。** 組織では「空間」は調整オーバーヘッドだ——二つのチームを同期させるコミュニケーションコスト、各半分の出力をマージ可能にするドキュメントコスト。分割統治は無料ではない；マージを保持するバッファ——会議、仕様、インターフェース——が必要だ。バッファをスキップすれば、合わない二つのソート済み半分ができる。マージが失敗するのは半分が間違っているからではなく、組み合わせ方を知らずに作られたからだ。

**🌍 人生**
人生の最大の問題——「キャリアを築く」「家族を育てる」「目的を見つける」——は不可能に感じる、それらが配列全体の問題だからだ。全ペアを比較して百万の要素をソートできない。だが問題を半分に切り、また切り、また切り、手に持てるほど小さくなるまで切れば——ソートできる。

人生のマージソート・アプローチ：**問題全体を解こうとするのをやめよ。切れ。** 「キャリアを築く」は「自分が何に向いているか」+「市場が何を必要としているか」になる。それぞれがまた切れる：「何に向いているか」は「どんなスキルがあるか」+「どんなスキルを学びたいか」になる。一つの決定になるまで切り続ける：「このコースを受ける」「この本を読む」「この役職に応募する」。自明に解ける。それから上にマージ：スキルをプロフィールに、プロフィールと市場ニーズをキャリアの方向に。

そして保証：**構造がカオスから守る。** 問題がどれほど圧倒的に感じても、半分に切り解をマージできれば、総コストは $O(n \log n)$ —— $O(n^2)$ ではない。問題全体に一度に直面することはない。$\log_2(n)$ レベルに直面し、各レベルはただ：切り、より小さなピースを解き、マージする。再帰が保護だ。レベルがバッファだ。問題全体を頭に持つ必要はない——一度に一レベル持ち、構造が残りを処理する。

そしてトレードオフ——空間コスト：**マージソートは中間結果の保持を要求する。** 切って忘れるだけではできない。各半分の解はマージが起きるまで*保持*されなければならない——メモリに、ノートに、計画に。切って中間の解を覚えないのはマージソートではない；散らすだけだ。人生の分割統治の空間コストは*進捗を追跡する*コストだ：ジャーナリング、計画、レビュー。マージするためにピースを保持するために $O(n)$ の空間を払う。スキップすれば、二つのソート済み半分があり、組み合わせられない——人生の二半分が一つの全体にならない。

**⚠️ アンチパターン**
*「問題を小さなピースに切って一つずつこなそう。」* それはマージソートではない——ただの……to-do リストだ。欠けているのは**マージ**だ。問題をサブ問題に切るのはアルゴリズムの半分にすぎない。$O(n^2)$ ではなく $O(n \log n)$ にするもう半分は——*解かれたサブ問題を首尾一貫した全体に組み合わせる*ことだ。プロジェクトをタスクに切り、各タスクを解き、結果を統合しなければ、ソート済みの断片の山があり、ソート済みの配列はない。マージはほとんどのプロジェクトが失敗する場所だ：切りでなく、解きでなく、*組み合わせ*で。マージにはピースがどうはまるかを知る必要がある——どんなインターフェースを共有するか、どんな順序か、二つのソート済み半分が出会う時にどんなコンフリクトが起きるか。切りは簡単だ。マージが芸術だ。切れてもマージできなければ、$O(n)$ で断片を作り $O(n^2)$ で乱雑を片付ける。マージはアルゴリズムの魂であり——プロジェクトの、人生の魂でもある。
