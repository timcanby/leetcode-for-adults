### 27. Quick Sort

> *ピボットを選び、配列を「ピボット以下」と「ピボット以上」に分割し、各側で再帰する。*

**🧩 アルゴリズム**
クイックソートは均等に分けない。**ピボットを選ぶ**——配列の一要素——それを支点にする。小さいものは左へ。大きいものは右へ。ピボットは最終位置に着地する。それから各側で再帰する。

ピボットは最小でも最大でもない。最善でも最重要でもない。ただ*ある*値で、基準点として選ばれたもの。魔法はピボットではなく**分割**にある：全てを一つの基準点に相対的に整理する動作で、問題を二つの独立したサブ問題に分ける。

```python
def quick_sort(nums):
    def sort(left, right):
        if left >= right:
            return

        pivot = nums[(left + right) // 2]
        i, j = left, right

        while i <= j:
            while nums[i] < pivot:
                i += 1
            while nums[j] > pivot:
                j -= 1

            if i <= j:
                nums[i], nums[j] = nums[j], nums[i]
                i += 1
                j -= 1

        sort(left, j)
        sort(i, right)

    sort(0, len(nums) - 1)
    return nums
```

> 時間 $O(n \log n)$ 平均、$O(n^2)$ 最悪 · 空間 $O(\log n)$

より深い原理：**進歩には完璧なバランスは要らない——基準点が要る。** マージソートは毎回完璧に半分に切る——優雅で保証付きだが、半分を保持する余分な空間が要る。クイックソートはピボットを選んでインプレースで分割する——乱雑で確率論的だが、バッファが不要だ。ピボットが概ね中央に落ちることを賭け、ほとんどの場合、それで十分だ。

トレードオフは決定的だ：**クイックソートは実践ではマージソートより速いが、$O(n^2)$ に劣化しうる。** ピボットが一貫して最悪の選択なら——最小または最大——各「分割」は一要素を剥がし残りで再帰する。$n$ レベルの再帰、各レベル $O(n)$。最悪ケースは理論上は珍しくない；実践では、ほとんどの入力が「十分にランダム」でピボットが概ね中央に落ちるから稀だ。だが*起こりうる*、そして起きた時、最速のはずのアルゴリズムが部屋で最遅になる。

教訓は脆弱性にある：**クイックソートの弱点はアルゴリズムではない——ピボットだ。** 良いピボットは $O(n \log n)$ にする。悪いピボットは $O(n^2)$ にする。同じアルゴリズム、同じコード、同じ構造——異なるピボット、異なるパフォーマンス。ピボットが全体を機能させるか崩壊させるかを決める変数だ。

**🏢 職場**
各再編にはピボットが必要だ——**他の全てがその周りに再配置される基準点。** 最もシニアな人ではない。最も重要なプロジェクトではない。ただ*ある*人、*ある*プロジェクト、*ある*値を錨として選び、分割する：「これはピボットに報告するか？これはピボットと整合するか？」

クイックソートの知恵：**完璧なバランスは要らない。ピボットと分割が要る。** チームリードを一人選ぶ。全てをその人に相対的に再編する：誰が上に報告し、誰が横に報告し、誰が独立か。ピボットは最良のリードである必要はない——分割が概ね均等になる*基準として十分*であればいい。80% が片側に偏れば、ピボットが悪かった。概ね 50/50 なら、ピボットは十分だった。

そして脆弱性：**ピボットが一貫して悪いとクイックソートは劣化する。** 組織では、それが「ピボット」——人、プロジェクト、原則——が極端すぎて全てが片側に偏る再編だ。最もジュニアな人を錨に選べば、他の全員が「上」になる。最もニッチなプロジェクトを選べば、他の何も「関連」しない。分割が失敗し、再帰が深まり、各ラウンドで一人だけ動く。それが $O(n^2)$ 再編：各再編決定が一人だけ動かし、もう一回のフルパスを必要とする。良いピボットは再編を速くする。悪いピボットは磨かせる。

解決策はより良いアルゴリズムではない——**より良いピボット**だ。問題を概ね半分に分けるピボットを選ぶ。最も極端な人ではない。最も極端なプロジェクトではない。中間にいる人——他のほとんどがその人に関連し、その役割が最も自然に組織を均衡した二半分に分ける人。ピボットがレバーで、分割が動き、バランスが速さを作る。

**🌍 人生**
各重大な人生の決断にはピボットが必要だ——**一つの値、一つの優先事項、一つの基準で、他の全てをその周りに整理するもの。**

「この仕事を引き受けるべきか？」ピボットは給与ではない。ピボットは名声ではない。ピボットは、持ち上げて他の全てを相対的に分割した時、人生を概ね半分に分ける値だ：「今私にとって何が最も重要か？」それを選ぶ。それより上は「yes」の山へ。それより下は「no」の山へ。ピボットは*最良*の値である必要はない——分割が均衡する*基準として十分*であればいい。

クイックソート式の決断：**全ての要因を均等に計るな。最も重要なものを一つ選び、それに相対的に分割し、残りで再帰する。** 百万要因の最適化に感じた決断が、ピボット + 分割 + 再帰になる。全てを頭に持つ必要はない。一つのピボットを持ち、それに相対的にソートし、残りが二つのより小さく管理しやすい山に落ちる。

そして脆弱性——$O(n^2)$ 人生：**ピボットが一貫して極端だと、各決断は一要因を剥がし残りで再帰する。** 最も極端な基準を選ぶ——「50万必要、リモート必須、スタートアップ必須、まさにその都市必須」——全てが分割に失敗する。各要因が孤立して処理され、毎回全量再計算される。決断に何カ月もかかる。均衡したピボット——「今私にとって何が最も重要か？」——は問題を半分にし、二つのより小さな山で再帰する。極端なピボット——「完璧な仕事」——は各パスで一要因を剥がし、永遠に収束しない。

知恵：**あなたのピボットはあなたの優先事項だ。** 最高の優先事項ではなく——*最も分割する*優先事項だ。持ち上げた時、人生の残りを概ね二つの等しい山に分けるもの：「これより上」と「これより下」。全てが片側に落ちれば、ピボットが極端すぎる。概ね半分に分かれれば、ピボットは正しい。アルゴリズムは完璧なピボットを求めない。*十分に良い*ものを求める——そして「十分に良い」とは「問題を分割できる」という意味だ。

**⚠️ アンチパターン**
*「全ての要因を均等に計って最適なバランスを見つける。」* それはクイックソートではない——$O(n^2)$ アプローチだ：全ての要因を全ての要因と比較し、全てのトレードオフを完全に評価し、全ての角度を同時に最適化する。ピボットの全ポイントは**全てを均等に計らないこと**だ。一つの基準点を選び、それに相対的にソートし、分割がサブ問題を小さくすると信じる。ピボットを選ぶことを拒めば——全ての要因が等しく重みを持ち、全ての考慮が等しく重要なら——決して分割しない。永遠に全てを全てと比較するだけだ。ピボットは妥協ではなく、*コミットメント*だ。一つの基準点にコミットし、その周りに分割し、分割が不完全でも*進歩*であることを受け入れる。$O(n \log n)$ の不完全な進歩は $O(n^2)$ の完璧な分析に勝る——ソートで、キャリアで、人生で。
