### 27. Quick Sort

> *选一个基准值，把数组分成"比基准小"和"比基准大"两边，然后各自递归。*

**🧩 算法**
快排不均匀地分。它**选一个 pivot**——数组里的一个元素——把它当支点。比它小的都去左边。比它大的都去右边。pivot 落在最终位置。然后两边各自递归。

pivot 不是最小的也不是最大的。不是最好的也不是最重要的。它只是*一个*值，被选为参照点。魔法不在 pivot——在**分区**：把所有东西相对一个参照点组织的动作，让问题分成两个独立的子问题。

```python
def quick_sort(nums):
    def sort(left, right):
        if left >= right:
            return

        pivot = nums[(left + right) // 2]
        i, j = left, right

        while i <= j:
            while nums[i] < pivot:
                i += 1
            while nums[j] > pivot:
                j -= 1

            if i <= j:
                nums[i], nums[j] = nums[j], nums[i]
                i += 1
                j -= 1

        sort(left, j)
        sort(i, right)

    sort(0, len(nums) - 1)
    return nums
```

> 时间 $O(n \log n)$ 平均，$O(n^2)$ 最坏 · 空间 $O(\log n)$

更深的原理：**进步不需要完美平衡——需要一个参照点。** 归并排序每次完美对半切——优雅、有保证，但需要额外空间。快排选一个 pivot 就地分区——凌乱、概率性的，但不需要缓冲区。它赌 pivot 大致在中间，而大多数时候，这就够了。

这个权衡是决定性的：**快排在实践中比归并快，但能退化到 $O(n^2)$。** 如果 pivot 一致地是最差选择——最小或最大——每次"分区"只剥一个元素然后对剩下的递归。$n$ 层递归，每层 $O(n)$。最坏情况在理论上不少见；在实践中少见，因为大多数输入"足够随机"使得 pivot 大致落在中间。但它*可能*发生，而一旦发生，本该最快的算法变成了屋里最慢的。

教训在脆弱性里：**快排的弱点不是算法——是 pivot。** 好的 pivot 让它 $O(n \log n)$。坏的 pivot 让它 $O(n^2)$。同样的算法、同样的代码、同样的结构——不同的 pivot，不同的表现。pivot 是决定整个东西成败的变量。

**🏢 职场**
每次重组都需要一个 pivot——**一个让其余一切围绕它重新排列的参照点。** 不是最资深的人。不是最关键的项目。只是*一个*人、*一个*项目、*一个*值被选为锚，然后你分区："这个向 pivot 汇报吗？这个和 pivot 对齐吗？"

快排的智慧：**你不需要完美平衡。你需要一个 pivot 和一次分区。** 选一个团队负责人。把一切相对他重新组织：谁向上汇报、谁平级汇报、谁独立。pivot 不需要是最好的负责人——只需*作为参照足够好*，让分区大致均匀。如果 80% 的人都在一边，pivot 选坏了。如果大致 50/50，pivot 够好。

而脆弱性是：**当 pivot 一致地坏，快排退化。** 在组织里，就是那次重组——pivot 选了最极端的人/项目/原则，一切都跑到一边。你选了最初级的人当锚，所以其他人都"在上面"。你选了最冷门的项目，所以没有别的跟它"相关"。分区失败，递归加深，每轮只移动一个人。那就是 $O(n^2)$ 重组：每次重组决定只动一个人、需要再来一轮完整扫描。好的 pivot 让重组快。坏的 pivot 让它磨。

解法不是更好的算法——是**更好的 pivot**。选能把问题大致对半分的 pivot。不是最极端的人。不是最极端的项目。中间那个——最多人跟他相关的、角色最自然地把组织分成均衡两半的。pivot 是杠杆；分区是动作；平衡才是快。

**🌍 人生**
每个重大人生决定都需要一个 pivot——**一个值、一个优先级、一条标准，让其余一切围绕它组织。**

"我该接这份工作吗？"pivot 不是薪水。pivot 不是声望。pivot 是那个当你举起来、把其余一切相对它分区时、把人生大致对半分的值："现在对我最重要的是什么？"选那个。在它上面的进"是"堆。在它下面的进"否"堆。pivot 不需要是*最好*的值——只需*作为参照足够好*，让分区均衡。

快排式的决策：**别等权每个因素。选最重要的那个，相对它分区，对其余递归。** 那个感觉像百万因素优化的问题变成 pivot + 分区 + 递归。你不需要把一切装在脑子里。你拿一个 pivot，相对它排，其余落成两个更小、更可控的堆。

而脆弱性——$O(n^2)$ 人生：**当你的 pivot 一致极端，每个决定只剥一个因素然后对其余递归。** 你选最极端的标准——"必须 50 万、必须远程、必须是初创、必须在我那个城市"——一切都分区失败。每个因素被孤立处理，每次全量重算。决定花了好几个月。均衡的 pivot——"现在对我最重要的是什么？"——把问题对半分，对两堆更小的递归。极端的 pivot——"那份完美的工作"——每次只剥一个因素，永远不收敛。

智慧是：**你的 pivot 就是你的优先级。** 不是你最高的优先级——你*最能分割*的优先级。当你举起它时把余生大致分成两半的那个："高于这个"和"低于这个"。如果一切都落一边，你的 pivot 太极端。如果大致对半分，你的 pivot 是对的。算法不要求完美的 pivot。它要求*够好*的——而"够好"意思是"能把问题分开"。

**⚠️ 反模式**
*"我等权每个因素然后找到最优平衡。"* 那不是快排——那是 $O(n^2)$ 做法：每个因素和每个因素比、每个权衡全量评估、每个角度同时优化。pivot 的全部意义在于**你不需要等权一切。** 你选一个参照点，相对它排，相信分区会让子问题更小。如果你拒绝选 pivot——如果每个因素等权、每个考虑等重——你永远不分区。你只是永远地把一切和一切比较。pivot 不是妥协；是*承诺*。你承诺一个参照点，围绕它分区，接受分区不完美但*是进步*。$O(n \log n)$ 的不完美进步胜过 $O(n^2)$ 的完美分析——在排序里、在职业里、在人生里。
