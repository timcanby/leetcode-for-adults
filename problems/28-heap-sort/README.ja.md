### 28. Heap Sort

> *配列からヒープを構築し、最大値を繰り返し末尾に抽出する。*

**🧩 アルゴリズム**
ヒープソートは走査も交換も挿入も選択もマージもピボットもしない。**ヒープに組織する**——各親が子より大きい構造——それから*収穫*する：ルート（最大値）を抜き出し、末尾に交換し、ヒープ性質を復元し、繰り返す。ソート済み領域は後ろから成長し、一回に一つの抽出された最大値ずつ。

ヒープは配列ではない。ヒープは配列に*課された関係*——親子の義務の集合で、各親が子より上位。同じ要素、異なる配置、異なるヒープ。構造はデータの中ではなく、データ*の間*のルールにある。

```python
def heap_sort(nums):
    n = len(nums)

    def sift_down(i, size):
        while True:
            largest = i
            left = i * 2 + 1
            right = i * 2 + 2

            if left < size and nums[left] > nums[largest]:
                largest = left
            if right < size and nums[right] > nums[largest]:
                largest = right

            if largest == i:
                break

            nums[i], nums[largest] = nums[largest], nums[i]
            i = largest

    # フェーズ1：ヒープ構築——ボトムアップ、最後の親からルートへ
    for i in range(n // 2 - 1, -1, -1):
        sift_down(i, n)

    # フェーズ2：最大値を抽出、末尾に交換、ヒープ復元、縮小
    for end in range(n - 1, 0, -1):
        nums[0], nums[end] = nums[end], nums[0]
        sift_down(0, end)

    return nums
```

> 時間 $O(n \log n)$——常に、保証付き · 空間 $O(1)$

より深い原理：**データを直接ソートするのではない——データに構造を課し、構造が代わりに順序を生み出す。** ヒープは局所的な義務の集合だ：各親は子より大きくなければならない。大局的知識はない。他の全要素との比較もない。ただ：「あなたは子より大きいか？」を各ノードで答える、ボトムアップで。

フェーズ1——**ヒープ構築**——ボトムから始まる。葉は既にヒープだ（自明——子がないから）。だから最後の親から始めて上に向かう。各 `sift_down` が一要素をそのレベルに押し下げる。ルートに到達する頃には、配列全体がヒープだ——各親が子より大きく、最大値がトップに。配列をソートしたのではない。*ルールシステム*を課した——そしてルールシステムが代わりにソートした。

フェーズ2——**収穫**——報酬だ。最大値は常にルートにある。それを末尾（最終位置）に交換し、新しいルートを下に篩ってヒープ性質を復元する。ソート済み領域は後ろから成長する。各抽出は $O(\log n)$——変位された要素が高々 $\log n$ レベル降りてそのレベルに着く。$n$ 回の抽出 → $O(n \log n)$。構造が仕事をする；あなたは収穫するだけ。

そして保証：**ヒープソートは最悪ケースでも $O(n \log n)$、インプレース、余分な空間なし。** マージソートの保証（$O(n^2)$ 劣化なし）とクイックソートの空間効率（バッファ不要）を持つ。トレードオフ：キャッシュフレンドリーでなく、直感的でなく、定数が悪い。ヒープの構造——暗黙的、配列ベース、インデックス計算で親子関係を計算——効率だが不透明だ。ソート済み配列のようにヒープを「読む」ことはできない。順序はあるが、それは構造に*エンコード*されており、表面には見えない。

**🏢 職場**
各人を各人と比較してチームをソートしない。**構造を課す**——報告階層で、各マネージャーがその直属の部下より上位——構造が代わりに順序を生み出す。

ヒープは組織図だ。*視覚的な*組織図（それはツリー）ではなく、*義務構造*：各マネージャーが直接の部下に責任を持つ。ルート——CEO——が最大値だ。ソート済み領域——「完了したプロジェクト」——は後ろから成長し、ルートが抽出されるにつれて：トップの人が成果を届け、結果がロックされ、残りのチームが再編される。

フェーズ1——**組織構築**：トップから始めない。ボトムから始める——葉ノード、個人貢献者——上に向かって。各管理レイヤーがボトムアップで追加される。ルートに到達する頃には、各マネージャーが部下より強く、最も優秀な人がトップに。全員を*比較*したのではない。*ルール*を課した：「各マネージャーは部下より強くなければならない」——ルールが階層を生み出した。

フェーズ2——**収穫**：トップの人が成果を届ける。ロック——そのプロジェクトは完了、その人の貢献は記録された。それからチームが再編：誰かが一歩出て隙間を埋め、`sift_down` がその人をそのレベルに押し下げ、次に優秀な人がトップに浮かぶ。ソート済み領域——完了したプロジェクト——は後ろから成長する。各抽出は一つのプロジェクトで、ヒープは $O(\log n)$ で再編される——$O(n)$ ではなく、ツリーの一本のパスだけ調整すればいいから。

そしてトレードオフ：**ヒープ構造は効率的だが不透明だ。** ソート済みリストのように組織図からチームのランキングを「読む」ことはできない。階層はあるが、報告関係に*エンコード*されており、表面には見えない。CEO が最大値だ——だが二番目に優秀な人は三レベル下、あるサブツリーに埋まっているかもしれない。構造は正しい（最大値は常に抽出可能）が、透明ではない。読みやすさを効率と引き替える。外部に*理解される*必要があるチームには——投資家、新人、公衆——ソート済み配列（透明なランキング）が良い。ただ*生産*する必要があるチームには——最善を抽出し、ロックし、再編し、繰り返す——ヒープが理想だ。

**🌍 人生**
全経験を全経験とランキングして人生をソートしない。**構造を課す**——局所的な義務の集合：「毎日はそれが生み出す日より良くなければならない」——構造が代わりに順序を生み出す。

ヒープは人生の義務システムだ。カレンダー（それはソート済み配列）ではなく、*関係構造*：各コミットメントはそれが作るサブコミットメントより大きくなければならない。健康がルートだ——仕事と人間関係より大きくなければ（重要でなければ）ならない、なぜならそれが崩れれば下の全てが崩れるから。仕事は健康の子——個々のタスクより大きくなければならない。人間関係はもう一つの子——個々の社会的約束より大きくなければならない。

フェーズ1——**人生ヒープ構築**：人生の目的（ルート）を決めることから始めない。ボトムから始める——日常の習慣、個々のコミットメント——上に向かって。各レベル：「この習慣はそれが生む習慣より大きいか？このコミットメントはそれが作るサブコミットメントより大きいか？」ルートに到達する頃には——健康、核——構造全体がヒープだ。各義務がそれが作る義務より大きい。最大値——最も重要なもの——がトップに。

フェーズ2——**収穫**：トップの優先事項が届けられる。それを抽出する——その日を生き、そのプロジェクトを完了し、その約束を果たす——ロックされる。ソート済み領域——生きた人生——は後ろから成長する。それから残りの構造が再編：次の優先事項がトップに浮かび、`sift_down` が変位された要素をそのレベルに押し下げ、ヒープが復元される。各日が一回の抽出。ヒープは $O(\log n)$ で再編される——人生のツリーの一本のパスであり、構造全体ではない。

そしてトレードオフ：**よく構造化された人生は外部者に不透明だ。** ソート済みリストのようにカレンダーから優先事項を「読む」ことはできない。構造はある——最も重要なものは常にトップに——が、コミットメント間の関係に*エンコード*されており、表面には見えない。「忙しく」見える人が効率的に最大値を抽出しているかもしれない。「リラックスして」見える人が完璧に管理されたヒープを持っているかもしれない。表面で構造を判断できない。ヒープは効率的で保証付きで不透明——そしてその不透明さが保証の代償だ。

そして知恵：**ヒープは大局的知識を必要としない。** マージソートは両半分を見る必要がある。クイックソートは配列全体を分割する必要がある。ヒープソートはただ知る必要がある：「あなたは子より大きいか？」——*局所的な*問いで、各ノードで答えられ、ボトムアップで。自分の人生が他の全員の人生とどう比較されるか知る必要はない。大局的に自分をランキングする必要はない。一つの局所的義務を維持するだけだ：**各優先事項はそれが作る優先事項より大きくなければならない。** 各レベルでこのルールを守れば、最大値——最も重要なもの——は常にトップに浮かぶ。探したからではなく、構造が*生み出した*からだ。

**⚠️ アンチパターン**
*「人生の全てを重要度でランキングしてから始める必要がある。」* それは配列を直接ソートすることだ——各要素を各要素と比較し、全順序を生み出し、それから行動する。最も直感的で最も麻痺的なアプローチ：ランキングに全精力を費やし、行動にゼロを費やす。ヒープは言う：**全順序は要らない。局所的義務が要る。** 全てを全てとランキングするな。各レベルで一つのルールを守るだけだ：「この優先事項はそれが作る優先事項より大きいか？」それを局所的に——各コミットメント、各日、各プロジェクトで——答えれば、大局的順序は自ずと整う。最大値は探したからではなく、構造が*届けた*から浮かぶ。大局的ランキングをスキップせよ。局所的ルールを課せ。構造が生み出すものを収穫せよ。ヒープの約束は、全体像を見る必要が決してないこと——各レベルとその一つ下のレベルの関係を尊重するだけでいい。$O(n \log n)$ 保証付き、インプレース、バッファなし——構造が代わりに覚えてくれるから。
