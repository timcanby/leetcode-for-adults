### 28. Heap Sort

> *把数组建成堆，然后反复把最大值提取到末尾。*

**🧩 算法**
堆排序不扫描、不交换、不插入、不选择、不归并、不选 pivot。它**组织成堆**——一个每个父节点都大于子节点的结构——然后*收割*：拔出根（最大值），交换到末尾，恢复堆性质，重复。已排序区域从后面增长，一次一个提取的最大值。

堆不是数组。堆是数组上*强加的关系*——一组父子义务，每个父节点都大于它的子节点。同样的元素，不同排列，形成不同的堆。结构不在数据里；结构在数据*之间*的规则里。

```python
def heap_sort(nums):
    n = len(nums)

    def sift_down(i, size):
        while True:
            largest = i
            left = i * 2 + 1
            right = i * 2 + 2

            if left < size and nums[left] > nums[largest]:
                largest = left
            if right < size and nums[right] > nums[largest]:
                largest = right

            if largest == i:
                break

            nums[i], nums[largest] = nums[largest], nums[i]
            i = largest

    # 阶段一：建堆——自底向上，从最后一个父节点到根
    for i in range(n // 2 - 1, -1, -1):
        sift_down(i, n)

    # 阶段二：提取最大值，交换到末尾，恢复堆，缩小范围
    for end in range(n - 1, 0, -1):
        nums[0], nums[end] = nums[end], nums[0]
        sift_down(0, end)

    return nums
```

> 时间 $O(n \log n)$——永远如此，有保证 · 空间 $O(1)$

更深的原理：**你不直接排序数据——你在数据上强加一个结构，结构替你产生顺序。** 堆是一组局部义务：每个父节点必须大于子节点。没有全局知识。不需要和每个其他元素比较。只是："你比你的子节点大吗？"在每个节点上回答，自底向上。

阶段一——**建堆**——从底部开始。叶子已经是堆了（平凡——它们没有子节点）。所以你从最后一个父节点开始向上走。每次 `sift_down` 把一个元素推到它的层级。当你走到根时，整个数组就是一个堆——每个父节点都大于它的子节点，最大值在顶部。你没有排序数组。你强加了一个*规则系统*——规则系统替你排好了。

阶段二——**收割**——是回报。最大值永远在根。你把它交换到末尾（它的最终位置），然后通过把新根向下筛来恢复堆性质。已排序区域从后面增长。每次提取 $O(\log n)$——被挤走的元素最多走 $\log n$ 层到它的层级。$n$ 次提取 → $O(n \log n)$。结构做功；你只收割。

而保证是：**堆排序最坏情况也是 $O(n \log n)$，原地，无额外空间。** 它有归并排序的保证（无 $O(n^2)$ 退化）和快排的空间效率（无需缓冲区）。代价：不如它们缓存友好、不如它们直觉、常数更差。堆的结构——隐式的、基于数组的、靠索引算术计算的父子关系——高效但不透明。你没法像读有序数组那样"读"一个堆。顺序在那，但它是*编码*在结构里的，不在表面可见。

**🏢 职场**
你不会通过比较每个人和每个人来排团队。你**强加一个结构**——汇报层级，每个管理者都大于他的下属——结构替你产生顺序。

堆就是组织架构图。不是*视觉上的*架构图（那是树），而是*义务结构*：每个管理者对他的直接下属负责。根——CEO——是最大值。已排序区域——"已完成的项目"——从后面增长，随着根被提取：最上面的人交付，结果锁定，剩余团队重新组织填补空缺。

阶段一——**建组织**：你不在顶部开始。你在底部开始——叶子节点，个人贡献者——向上走。每层管理层从底向上添加。当你走到根时，每个管理者都大于他的下属，最优秀的人在顶部。你没有*比较*所有人。你强加了一条*规则*："每个管理者必须比他的下属强"——规则产生了层级。

阶段二——**收割**：最上面的人交付结果。锁定——那个项目完成了，那个人的贡献记录了。然后团队重组：有人站出来填空，`sift_down` 把他推到他的层级，下一个最优秀的人浮到顶部。已排序区域——已完成项目——从后面增长。每次提取是一个项目，堆在 $O(\log n)$ 内重组——不是 $O(n)$，因为只有树中的一条路径需要调整，不是整个结构。

而代价：**堆结构高效但不透明。** 你没法像读排序列表那样"读"团队的排名。层级在那，但*编码*在汇报关系里，不在表面可见。CEO 是最大值——但第二好的人可能在三层以下，埋在某个子树里。结构是正确的（最大值总是可提取的），但不透明。你用可读性换效率。对于需要被外人*理解*的团队——投资人、新人、公众——有序数组（透明排名）更好。对于只需要*产出*的团队——提取最好的、锁定、重组、重复——堆是理想。

**🌍 人生**
你不会通过把每段经历和每段其他经历排名来排你的人生。你**强加一个结构**——一组局部义务："每一天都必须大于它产生的那些日子"——结构替你产生顺序。

堆是你人生的义务系统。不是日历（那是有序数组），而是*关系结构*：每个承诺必须大于它创建的子承诺。你的健康是根——它必须大于（重要于）你的工作和人际关系，因为如果它塌了，它下面的一切都塌。你的工作是健康的子节点——它必须大于你的单个任务。你的人际关系是另一个子节点——它们必须大于你的单个社交承诺。

阶段一——**建人生堆**：你不在决定人生使命（根）开始。你在底部开始——日常习惯、单个承诺——向上走。每层："这个习惯大于它产生的习惯吗？这个承诺大于它创建的子承诺吗？"当你走到根——你的健康、你的核心——整个结构是一个堆。每个义务都大于它创建的义务。最大值——最重要的东西——在顶部。

阶段二——**收割**：最上面的优先级交付。你提取它——你过了那一天、完成了那个项目、兑现了那个承诺——锁定了。已排序区域——你活过的人生——从后面增长。然后剩余结构重组：下一个优先级浮到顶部，`sift_down` 把被挤走的元素推到它的层级，堆恢复了。每天是一次提取。堆在 $O(\log n)$ 内重组——人生树中的一条路径，不是整个结构。

而代价：**一个结构良好的人生对局外人是不透明的。** 你没法像读排序列表那样"读"一个人的优先级。结构在那——最重要的东西总在顶部——但*编码*在承诺之间的关系里，不在表面可见。看起来"忙"的人可能在高效地提取最大值。看起来"放松"的人可能有一个完美维护的堆。你没法从表面判断结构。堆高效、有保证、不透明——而不透明就是保证的代价。

而智慧是：**堆不需要全局知识。** 归并排序需要看到两半。快排需要分区整个数组。堆排序只需要知道："你比你的子节点大吗？"——一个*局部*问题，在每个节点上回答，自底向上。你不需要知道你的人生和其他所有人的人生相比如何。你不需要全局排名自己。你只需维护一条局部义务：**每个优先级必须大于它创建的优先级。** 在每一层保持这条规则，最大值——最重要的东西——总浮到顶部。不是因为你搜索了它。是因为结构*产出*了它。

**⚠️ 反模式**
*"我得先把人生里所有事按重要性排好才能开始。"* 那是直接排序数组——每个元素和每个元素比，产生全序，然后行动。最直觉也最瘫痪：你把全部精力花在排名上，没有行动。堆说：**你不需要全序。你需要局部义务。** 别把一切和一切排名。只在每层维护一条规则："这个优先级大于它创建的优先级吗？"局部回答——每个承诺、每一天、每个项目——全局秩序自己搞定。最大值浮上来不是因为你猎了它，是因为结构*交付*了它。跳过全局排名。强加局部规则。收割结构产出的东西。堆的承诺是你永远不需要看全貌——你只需尊重每层和它下面那层之间的关系。$O(n \log n)$ 有保证，原地，无缓冲——因为结构替你记住了。
