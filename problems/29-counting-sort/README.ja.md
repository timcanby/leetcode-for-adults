### 29. Counting Sort

> *各値の出現回数を数え、順序通りに配列を再構築する。*

**🧩 アルゴリズム**
カウンティングソートは比較しない。交換も分割もマージもピボットもヒープ化もしない。**数える**——各値の頻度を数え、最小から最大までカウントを歩き、記録された回数だけ各値を書き出す。結果はソート済み。比較は一度も起きなかった。

アルゴリズム全体は二パス：一パス目、各値の頻度を `value - min` でインデックスされた `count` 配列に記録。二パス目、`count` 配列を歩き、順序通りに元の配列を上書き。それだけ。順序は要素を比較して*発見*されたのではない——カウント配列の構造に*固有*で、インデックスが値だから。

```python
def counting_sort(nums):
    if not nums:
        return nums

    lo = min(nums)
    hi = max(nums)
    count = [0] * (hi - lo + 1)

    for x in nums:
        count[x - lo] += 1

    idx = 0
    for offset, freq in enumerate(count):
        value = offset + lo
        for _ in range(freq):
            nums[idx] = value
            idx += 1

    return nums
```

> 時間 $O(n + k)$、$k$ = 値の範囲 · 空間 $O(k)$

より深い原理：**構造が既にそこにある時、発見する必要はない——数えるだけでいい。**

比較ベースのソート——バブル、選択、挿入、マージ、クイック、ヒープ——全てが無知を仮定する。値が何かわからないから、順序を*発見*するために比較する。カウンティングソートは知識を仮定する：値は*既知の範囲*から来る、だから順序は値自身にエンコードされている。`3` と `7` のどちらが小さいか知るために比較する必要はない。数えるだけ：「3 はいくつ？7 はいくつ？」——そして順序通りに書く。

トレードオフは範囲だ。カウンティングソートは $O(n + k)$ で、$k$ は最小と最大の間の広がり。値が年齢（$k \approx 100$）やテストスコア（$k \approx 100$）なら、猛烈に速い——$O(n)$、線形、無敵。値が 64 ビット整数（$k = 2^{64}$）なら、使用不能——カウント配列だけで全メモリを超える。カウンティングソートは値の範囲が小さい時に速く、広い時に遅い。優雅に劣化しない——圧倒的に機能するか、全く機能しないか。

そして知恵：**数えられるものを比較する必要はない。** 比較ベースのアプローチ——全要素を全要素と比べる——はデータについて*何も知らない*時の*汎用*解だ。だが*何かを*知っている時——値が有界範囲から来る、カテゴリが有限、構造が見える——汎用解は無駄だ。$O(n \log n)$ の比較で、値の頻度に既にエンコードされている答えを買っている。頻度を数えよ。範囲を歩め。$O(n)$ で完了。範囲の知識*が*アルゴリズムだ。

**🏢 職場**
ほとんどの組織の問題は比較問題として扱われる：「A は B より良いか？プロジェクト X は Y より重要か？」——無限のペアワイズ比較、パフォーマンスレビュー、優先度マトリクス。それは $O(n \log n)$ アプローチだ：全員を全員と比較し、ランキングを発見する。

だが時には比較する必要がない。構造が既に見えている時。「各レベルに何人いるか？各カテゴリに何プロジェクトあるか？各優先度に何タスクあるか？」——値が既知の有界範囲（3 つのシニアリティレベル、5 つの優先度、4 種類のプロジェクト）から来れば、カウントで十分だ。

組織マネジメントのカウンティングソート・アプローチ：**カテゴリを数えられる時に個人を比較するのをやめよ。** 50 人のエンジニアを互いにランク付けする（$O(n \log n)$ の比較、高コストで政治的）代わりに、数える：「シニアは何人？ミッドは何人？ジュニアは何人？」カウント配列を歩く：シニアのスロットを先に埋め、次にミッド、次にジュニア。誰も比較されなかった。レベルの構造が順序を*生み出した*。

そしてトレードオフ——範囲：**カウンティングソートは範囲が有界で既知の時にのみ機能する。** 組織に 3 レベルあれば、カウントは瞬時。50 点満点で各エンジニアにユニークなスコアをつけようとすれば、カウントは無用——$k = 50$ が 50 人の中で、比較に戻る。洞察：**粗いカテゴリで十分な時に細かい差別化を作るな。** 5 つの優先度で十分なら 5 を使え。$O(n \log n)$ の比較領域に押し戻す 50 点のスコアリング基準を発明するな。有界範囲は贈り物だ。無界の比較は税金だ。範囲を保て；それ以上細分化する衝動に抵抗せよ。

**🌍 人生**
ほとんどの人生の決断は比較問題として扱われる：「オプション A は B より良いか？都市 X は Y より良いか？キャリア P は Q より良いか？」——無限の計量、ランキング、最適化。それは $O(n \log n)$ 人生だ：全オプションを全オプションと比較し、「最善の」選択は常に手の届かないところに、もう一つ比較ができるから。

だが時には比較する必要がない。カテゴリが既に見えている時。「価格範囲内の都市はいくつ？上位 3 スキルにマッチするキャリアはいくつ？必要な深さの人間関係はいくつ？」——値が有界範囲（手頃な都市、マッチするキャリア、互換性のある人）から来れば、カウントで十分だ。

人生のカウンティングソート・アプローチ：**数えられるカテゴリがある時に全オプションを比較するのをやめよ。** 100 の都市を互いにランク付けする必要はない。数える必要がある：「手頃なのはいくつ？私の業界があるのはいくつ？家のように感じるのはいくつ？」カウント配列を歩く：三つのカテゴリ全てにマッチする都市があなたの範囲だ。比較は不要。カテゴリの構造が答えを*生み出した*。

そして知恵——意思決定麻痺から解放するもの：**最善を見つける必要はない。十分に良いものを数えるだけでいい。** 比較アプローチは要求する：「*最善の*都市、*最善の*キャリア、*最善の*パートナーはどれ？」——$O(n^2)$ や $O(n \log n)$ の問題で、保証された答えがない、「最善」は動く標的だから。カウントアプローチは問う：「十分に良いのはいくつ？私のカテゴリに合うのはいくつ？」——$O(n)$ の問題で、具体的な答えがある。頻度を数えよ。範囲を歩め。答えは「唯一最善のオプション」ではなく——「合うオプションの集合」だ。そして集合が空でないことに気づいた時——住める都市が 7 つ、追えるキャリアが 12、一生を共にできる人が 5 人——比較の不安は溶ける。*最善*を探していたのではない。*十分に良いもの*を探していたのだ。カウントが数を教える。そして数が答えだ。

**⚠️ アンチパターン**
*「全オプションを比較して絶対的に最善を見つける必要がある。」* それはカウンティングソートの問題に比較ソートを適用すること——$O(n \log n)$ の比較で、カテゴリに既にエンコードされている答えを買うこと。オプションが有界範囲から来るなら——手頃な都市、マッチするキャリア、互換性のある人——「最善」は幻だ。唯一の最善はない。*十分に良いオプションの範囲*があり、カウントが $O(n)$ で範囲を与える。「最善」への執着が意思決定を $O(n^2)$ にするものだ：全オプションを全オプションと比較し、どのオプションも十分でない、より良いものがあるかもしれないから。合うものを数えよ。範囲を歩め。集合から一つ選べ。カウンティングソートの知恵は：**範囲が答えだ。** 最大値ではなく——境界内に収まる値の集合だ。最善を探すのをやめ、合うものを数え始めれば、意思決定は $O(n^2)$ から $O(n)$ になる。あなたが選んだカテゴリ——あなたが設定した境界——*が*アルゴリズムだ。良い境界を選び、中にあるものを数えれば、「最善」は自ずと整う。
