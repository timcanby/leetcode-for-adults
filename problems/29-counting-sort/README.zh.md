### 29. Counting Sort

> *统计每个值出现的次数，然后按顺序重建数组。*

**🧩 算法**
计数排序不比较。它不交换、不分区、不归并、不选 pivot、不堆化。它**计数**——统计每个值的频率，然后从最小到最大走一遍计数，按记录的次数写出每个值。结果有序。从未发生过任何比较。

整个算法就两遍遍历：第一遍，把每个值的频率记进 `count` 数组（按 `value - min` 索引）。第二遍，走 `count` 数组，按序覆盖原数组。就这。顺序不是通过比较元素*发现的*——它是*固有*在计数数组的结构里的，因为索引就是值。

```python
def counting_sort(nums):
    if not nums:
        return nums

    lo = min(nums)
    hi = max(nums)
    count = [0] * (hi - lo + 1)

    for x in nums:
        count[x - lo] += 1

    idx = 0
    for offset, freq in enumerate(count):
        value = offset + lo
        for _ in range(freq):
            nums[idx] = value
            idx += 1

    return nums
```

> 时间 $O(n + k)$，$k$ = 值的范围 · 空间 $O(k)$

更深的原理：**当结构已经在那，你不需要发现它——你只需计数。**

比较排序——冒泡、选择、插入、归并、快排、堆排——都假设无知。它们不知道值是什么，所以通过比较来*发现*顺序。计数排序假设有知：值来自一个*已知范围*，所以顺序已经编码在值本身里。你不需要比较 `3` 和 `7` 来知道谁更小。你只需计数："几个 3？几个 7？"——然后按序写出。

代价是范围。计数排序是 $O(n + k)$，$k$ 是最小值和最大值之间的跨度。如果值是年龄（$k \approx 100$）或考试分数（$k \approx 100$），快如闪电——$O(n)$，线性，无敌。如果值是 64 位整数（$k = 2^{64}$），不可用——计数数组本身就超出所有内存。计数排序在值范围小时快、范围大时不可用。它不优雅地退化——要么漂亮地工作，要么完全不工作。

而智慧是：**你能计数的就不需要比较。** 比较的做法——每个元素和每个元素比——是你对数据*一无所知*时的*通用*解。但当你*确实*知道一些——值来自有界范围、类别有限、结构可见——通用解就是浪费。你在用 $O(n \log n)$ 次比较买一个已经编码在值频率里的答案。计数。走范围。$O(n)$ 搞定。对范围的认知*就是*算法。

**🏢 职场**
大多数组织问题被当成比较问题处理："A 比 B 好吗？X 项目比 Y 项目重要吗？"——无尽的成对比较、绩效评估、优先级矩阵。那是 $O(n \log n)$ 做法：比较一切，发现排名。

但有时候你不需要比较。有时候结构已经可见。"每个级别有多少人？每个类别有多少项目？每个优先级有多少任务？"——如果值来自已知、有界的范围（3 个资历级别、5 个优先级、4 种项目类型），计数就够了。

计数排序的组织管理：**能数类别就别比较个体。** 别把 50 个工程师两两排名（$O(n \log n)$ 次比较，又贵又政治），计数："几个 senior？几个 mid？几个 junior？"走计数数组：先填 senior 槽位，再 mid，再 junior。没有人被比较。级别的结构*产出*了顺序。

而代价——范围：**计数排序只在范围有界且已知时有效。** 如果组织有 3 个级别，计数即时。如果组织试图在 50 分制上给每个工程师独特打分，计数无用——$k = 50$ 在 50 人里，你回到了比较。洞察是：**粗类别够用就别造细分。** 如果 5 个优先级够，用 5。别发明一个 50 分评分标准把你逼回 $O(n \log n)$ 比较领域。有界范围是礼物。无界比较是税。保护范围；抵制超出范围细分的冲动。

**🌍 人生**
大多数人生决定被当成比较问题处理："A 比 B 好吗？城市 X 比城市 Y 好吗？职业 P 比职业 Q 好吗？"——无尽地权衡、排名、优化。那是 $O(n \log n)$ 人生：每个选项和每个选项比，"最好的"选择永远差一点够不着，因为还有一个比较可做。

但有时候你不需要比较。有时候类别已经可见。"有多少城市在我的价格范围里？有多少职业匹配我前三个技能？有多少关系达到了我需要的深度？"——如果值来自有界范围（负担得起的城市、匹配的职业、兼容的人），计数就够了。

计数排序的人生做法：**能数对你重要的类别就别比较每个选项。** 你不需要把 100 个城市两两排名。你需要计数："几个负担得起？几个有我的行业？几个感觉像家？"走计数数组：三个类别都匹配的城市是你的范围。不需要比较。类别的结构*产出*了答案。

而智慧——让你从决策瘫痪中解放的：**你不需要找最好的。你需要数有多少够好的。** 比较的做法要求："哪个是*最好的*城市、*最好的*职业、*最好的*伴侣？"——一个 $O(n^2)$ 或 $O(n \log n)$ 的问题，没有保证的答案，因为"最好"是个移动靶。计数的做法问："有多少够好？有多少符合我的类别？"——一个 $O(n)$ 的问题，有具体答案。计数。走范围。答案不是"唯一最好的选项"——是"符合的选项集合"。当你意识到集合不空——有 7 个你能住的城市、12 条你能追的职业、5 个你能共度一生的人——比较焦虑消融了。你不是在找*最好的*。你是在找*足够多好的*。计数告诉你数量。数量就是答案。

**⚠️ 反模式**
*"我得比较每个选项找到绝对最好的。"* 那是用比较排序做计数排序的事——用 $O(n \log n)$ 次比较买一个已编码在类别里的答案。如果选项来自有界范围——负担得起的城市、匹配的职业、兼容的人——"最好"是幻影。没有唯一最好。有*一组够好的选项*，计数在 $O(n)$ 内给你范围。对"最好"的执念就是让决策变成 $O(n^2)$ 的东西：每个选项和每个比，没有选项足够，因为可能有边际更好的。数符合的。走范围。从集合里选一个。计数排序的智慧是：**范围就是答案。** 不是最大值——是符合边界的值的集合。当你停止找最好的开始数符合的，决策从 $O(n^2)$ 变成 $O(n)$。你选的类别——你设的边界——*就是*算法。选好边界，数里面的，"最好"自己搞定。
