### 31. Delete a Value from a Linked List

> *値が target に等しい最初のノードを見つけて削除する。新しいヘッドを返す。*

**🧩 アルゴリズム**
削除自体は自明だ——一行：`prev.next = cur.next`。ノードは消えた。リストは直った。難しいのは削除の*周り*の全て：正しいノードまで歩く、ターゲットがヘッドの場合を処理する、切断時に糸を失わないこと。

`dummy` センチネルがトリックだ。ヘッドの*前に*座るセンチネルを作る——`dummy.next = head`——そして `head` ではなく `dummy` から歩き始める。なぜか？ もしターゲットが*ヘッド*なら、それを指す `prev` が必要だ——だがヘッドには前身がない。dummy *が*その前身だ。それは全ノード——ヘッドを含む——の後ろに誰かがいるようにするために存在する。「もし削るのが最初なら？」というエッジケースに直面することは永遠にない、dummy が最初のノードを特別ではなくしたからだ。

```python
def delete_value(head, target):
    dummy = ListNode(0, head)
    prev = dummy
    cur = head

    while cur:
        if cur.val == target:
            prev.next = cur.next
            break

        prev = cur
        cur = cur.next

    return dummy.next
```

> 時間 $O(n)$ · 空間 $O(1)$

より深い原理：**そのものを削除するのではない——それを指すものをリダイレクトする。** ノード自体は破壊されない。*孤立化*される。かつてそれに届いたポインタがそれを飛び越える。ノードはメモリにまだ存在し、値を持ち、`next` を持つ——しかし誰もそこに到達できない。鎖から切られたのであって、存在から削除されたのではない。削除は*再ルーティング*であり、破壊ではない。

そして `dummy` の知恵：**前駆を作れば、全てのエッジケースに前駆がある。** ヘッドが特別なのは、唯一 `prev` のないノードだからだ。dummy がその特別さを取り除く。「もしヘッドなら？」を別ケースとして扱う代わりに、ヘッドを*特別ではなくする*——前駆を与える。エッジケースは消去されない——*溶ける*、それを生んだ条件（「前駆なし」）がもはや存在しないから。エッジケースを処理したのではない。*排除*した——構造を変えてそれが決して起きないようにした。

**🏢 職場**
誰かを解雇する時——あるいはプロジェクト、プロセス、ポリシーを削除する時——除去の行為はシンプルだ：一つの決定、一つの発表、一つのリダイレクト。難しいのは*除去の周りのコンテキスト*：そこまで歩く、ポジショニング、決定の前の対話。そして最も難しい：削除するのが*ヘッド*——リーダー、創業者、柱——なら？

`dummy` の知恵：**コンテキストを作れば、全ての除去にコンテキストがある。** ヘッドを解雇するのが他の誰かより難しい理由は、ヘッドには前駆がないように見えるからだ——上に、除去を構造的に普通に感じさせる人がいない。だが `dummy` を作っていれば——ヘッドの*上*に座る取締役会、アドバイザー、フレームワーク、ガバナンス構造——ヘッドはもう特別ではない。前駆がある。除去は `prev.next = cur.next`：取締役会が鎖をリダイレクトする。ヘッドは孤立化され、破壊されない。組織は続く——`return dummy.next`——新しいヘッドが自然に浮かぶ。

そして原理：**人を破壊するのではない——報告線をリルートする。** 人はまだいる。スキル、関係、歴史——全てそこにある。だが鎖はもはや彼らに届かない。リルートが除去だ。破壊は不要だ——そして通常は逆効果。誰かの影響力を消すためにその人を抹消する必要はない。かつて彼らに届いたポインタをリダイレクトするだけだ。

**🌍 人生**
人生から何かを削除する時——習慣、約束、人間関係、あるバージョンの自分——除去はシンプルだ：一つのリダイレクト、一つの「もう終わり」、一つの `prev.next = cur.next`。難しいのは*コンテキスト*：ポジショニング、決定まで歩く、切る前の対話。

そして最も難しい：削除するのが*ヘッド*——あなたの中核のアイデンティティ、主要な役割、何年もリストの先頭だったもの——なら？「私はもう弁護士ではない」「私はもう妻ではない」「私はもう面白い人ではない」。ヘッドには前駆がない。それより前にリダイレクトできるものがない。基盤を引き抜くような感じだ。

`dummy` の知恵：**アイデンティティのために前駆を作れ。** `dummy` は、いかなる単一の役割の*前にも外にも*存在するあなた——役割を見ている気づき、仕事より前の価値、タイトルと同一ではない自己。`dummy` を持っていれば——一つのノードに縛られない自己感——どの役割も特別ではない。ヘッドの削除は実存的危機ではなく；`prev.next = cur.next` だ。役割が孤立化され、自己ではない。`return dummy.next`——あなたが次に成るものが自然に浮かぶ。鎖は続く、dummy がずっとそれを持っていたから。

そして原理：**古い自己を破壊するのではない——リルートする。** 習慣はメモリにまだある。古い役割はまだあなたを形作った。人間関係は実際に起きた。それを抹消しない。かつてそれに届いたポインタをリダイレクトする。人生の `next` は今や新しい方向を指す——古いノードは過去にあり、現在の鎖からは届かないが、破壊されていない。忘れられていない。ただ*もはや鎖が行く場所ではない*。削除はリルートであり、焼却ではない。そして鎖はより長く——より健全に——リルートされたことで。

**⚠️ アンチパターン**
*「古いものを完全に破壊してから前に進める必要がある。」* それは `prev.next = cur.next` ではなく `del` ノードしようとすることだ。古い自己——古いキャリア、古い人間関係、古い習慣——を存在から抹消しようとしている。だがノードはメモリにある。それがあなたを形作った。あなたの一部だ。`del` すれば鎖が壊れる——記憶、スキル、それがくれた成長と共に。`dummy` アプローチは言う：破壊するな。リダイレクトせよ。古いノードは抹消される必要はない；*現在の鎖から到達不能*である必要があるだけだ。歩き続けよ。`prev.next = cur.next`。古いあなたはまだメモリに——あなたを形作った、まだ重要だ——だが鎖はもう進んだ。`return dummy.next`。新しいヘッド。次の役割。次の章。古いものの死ではなく——鎖のリルート。
