### 33. Longest Palindromic Substring

> *前からも後ろからも同じに読める最長の部分文字列を見つける。*

**🧩 アルゴリズム**
全部分割文字列の総当たり確認は $O(n^3)$——遅すぎる。DP の洞察：大きな部分文字列が回文だとゼロから証明しない。二つの安い事を確認する：

1. 両**端**は一致するか？（`s[i] == s[j]`）
2. その**間**は既に回文か？（`dp[i+1][j-1]`）

両方真なら、`s[i..j]` は回文だ。「内側は解済み」の部分が再帰——より短い部分文字列は全て既に計算済みだから、中央の答えはそこに待っている。

```python
def longestPalindrome(s):
    n = len(s)
    dp = [[False] * n for _ in range(n)]
    start = 0
    best = 1
    for i in range(n - 1, -1, -1):
        for j in range(i, n):
            if s[i] == s[j] and (j - i <= 2 or dp[i+1][j-1]):
                dp[i][j] = True
                if j - i + 1 > best:
                    start = i
                    best = j - i + 1
    return s[start:start + best]
```

> 時間 $O(n^2)$ · 空間 $O(n^2)$

より深い原理：**長い回文は、一致する両端を着けた短い回文にすぎない。** 大きな対称体を直接作らない。小さいものを先に作り、それから問う：「内側が既に完璧なら、外側に一致する二文字を包めるか？」それが手法全体だ。内側が重労働をし、両端は $O(1)$ の確認だ。

そしてループ順序が重要——`i` は**後ろ**へ（`n-1 → 0`）、`j` は `i` から前へ。`dp[i+1][j-1]` が存在する前に `dp[i][j]` は埋められないから、*より小さい*問題（より短い部分文字列、より大きい `i`）を先に解かねばならない。**大規模で対称性を認証する前に、全てのより小さい規模で認証せねばならない。** 順序は装飾ではない——それ*が*依存関係だ。

**🏢 職場**
組織の「回文」は、*両方*の方向から一貫する決定や物語——トップダウンの物語とボトムアップの現実。リーダーが別のことを言い、現場が別のことを生きる時、その部分文字列は回文ではない。壊れている。

DP の教訓：**組織全体を一度に一貫させようとしない。** まず局所的に一貫させよ。小チームを回文にせよ——彼らの宣言する目的は実際の行動と一致し（`s[i] == s[j]`）、彼らの*間*のチームは既に健康だ（`dp[i+1][j-1]`）。内側が完璧なら、より大きな組織は両端が一致するだけでいい。大きな回文は一致する境界を持つ小さな回文にすぎない——トップダウンの書き直しではない。

そしてループ順序：**外側の物語を断言する前に内側の機能不全を直せ。** 「今は整合している」と宣言するが中間チームが壊れたままの再編は `dp[i][j] = False`——`dp[i+1][j-1]` 確認が失敗する。全てのより小さい単位が既に一貫するまで、組織全体の対称性を認証できない。内側から始めよ。外へ働け。中間が立てば、両端は安い。

**🌍 人生**
前からも後ろからも同じに読める人生は、**誠実さ（integrity）**のある人生——あなたの唱える価値が実際の行動と、あらゆる角度から一致する。その最長の部分文字列は、言う自分と在る自分が一致する、人生の最長の区間だ。

DP の教訓：**大げさな姿勢一つで誠実さを達成するのではない。** 局所的に達成する。各小さな選択が回文確認だ：この縁で言葉は行動と一致するか（`s[i] == s[j]`）、その間の人生区間は既に一貫するか（`dp[i+1][j-1]`）？両方真なら、その区間は完璧だ。誠実さの途切れない長区間は大きな決意で築かれるのではない——既に完璧な内側を二つの一致する端で包む、何千もの小さな回文によって築かれる。

そしてループ順序——最も重要な部分：**誠実さは内側から外へ、小さいものから築く。** より小さい区間が完璧になる前に、*人生全体*が一貫すると認証できない（`dp[0][n-1]`）。「完全に変わった」と宣言するが内側がまだ矛盾している人は、`dp[i+1][j-1]` が存在する前に `dp[i][j]` を確認している——偽が返る。まず内側を変えよ。両端に従わせよ。人生の最長回文は、小さな一貫区間を一つずつ稼いで得る。

**⚠️ アンチパターン**
*「人生/組織を一貫するよう書き直す——外側からやり直す。」* それは `dp[i+1][j-1]` が存在する前に `dp[i][j]` を計算することだ。その大きな回文——「新しい私」「整合したチーム」「変革された文化」——を宣言するが、内側はまだ壊れているから確認は失敗する。両端は一致するかもしれない（今は*正しい*ことを言う）が、一貫した中間がなければ全体は `False`。DP 手法はこれを拒む：内部が*既に*回文である部分文字列の上でのみ対称を拡張する。外側の文字を強制的に一致させて長い回文を得るのではない。内側を完璧にし、それを包むことで得る。小さく始めよ。内側を真にせよ。長さを育てよ。外への一貫の拡張は安い——それを内側で*稼ぐ*ことが仕事だ。
