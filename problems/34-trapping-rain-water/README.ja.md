### 34. Trapping Rain Water

> *雨の後、棒の間に溜まる水の量を計算する。*

**🧩 アルゴリズム**
任意の位置 `i` で溜まる水は二つのもので決まる： `i` の**左**の最高の棒と、 `i` の**右**の最高の棒。水はその二つの壁の**より低い**方まで満ちる——低い壁が溢れる側だから。だから：

$$\text{water}[i] = \min(\text{left\_max}[i],\ \text{right\_max}[i]) - \text{height}[i]$$

`left_max`（左→右の走査最大）と `right_max`（右→左の走査最大）を事前計算し、全インデックスの溜まる水を合計する。

```python
def trap(height):
    n = len(height)
    if n == 0:
        return 0
    left = [0] * n
    right = [0] * n
    left[0] = height[0]
    for i in range(1, n):
        left[i] = max(left[i - 1], height[i])
    right[-1] = height[-1]
    for i in range(n - 2, -1, -1):
        right[i] = max(right[i + 1], height[i])
    return sum(min(left[i], right[i]) - height[i] for i in range(n))
```

> 時間 $O(n)$ · 空間 $O(n)$

より深い原理：**ある位置が溜める水はその*弱い*側で決まる。** 高い壁ではない。平均でもない。二つの**最小値**だ。高い壁は `i` に溜まる水には無関係——無限に高くしても溜まる水は一滴も増えない。低い壁だけが天井を決める。これはボトルネック原理だが、*保持容量*の問いに反転されている：容量 = min(左, 右)、強い壁は弱い壁を超えて寄与しない。

そして構造：**何が保持されるかを知るには、*両方*の方向を見ねばならない。** `i` の水は左の最高壁*と*右の最高壁の両方に依存する。単方向の視点——左だけ、過去だけ——は容量について何も語らない。右最大も要る。ある瞬間が何を保持できるかを知るには、その*両側*の最高の支持が要り、既に生きた側だけではない。

**🏢 職場**
価値を保持するプロジェクトの能力——収益、影響、学習——は強い境界ではなく、弱い境界で制限される。技術チームが世界クラス（左壁高）だが go-to-market が弱い（右壁低）なら、プロジェクトは弱い GTM の許す量しか保持しない。より多くのエンジニアリングを注いでも水は上がらない——GTM 天井が直ちに溢す。

罠：**組織は強みに過剰投資する。** 強い側は見え、祝われ、資金を得やすい。弱い側は見えず、華がなく、認めるのが難しい。だが容量 = min(左, 右)。強い側は既に天井を超えている；そこの一ドルは無駄だ。弱い側*が*天井だ。GTM を直せ。エンジニアリングは決してボトルネックではなかった。

そして構造：**両方向で評価せねばならない。** プロジェクトの真の容量には、背後にある最高のもの（チーム、技術、歴史）*と*前にある最高のもの（市場、需要、タイミング）の両方が要る。「良い技術がある！」（左壁）だけを見ては、右壁の天井に盲目になる。プロジェクトが実際に保持できるものを知るには両方の最大が要る。

**🌍 人生**
あなたが保持する「水」——幸福、容量、平静、蓄積された喜び——は強い限界ではなく、*弱い*限界で制限される。収入の上限が天まで高くても健康の下限が低ければ、その高い収入の価値は保持できない。健康下限の許す量だけを保持する。低い壁が人生の天井だ。

罠：**人は高い壁をより高くする。** より多くの収入、より多くの地位、より多くのスキル——一方低い壁（健康、休息、人間関係）はそのまま。追加収入は保持された幸福を一滴も上げない、健康壁が溢すから。あなたは感じる：何も買わなかった昇給、平静をもたらさなかった昇進。それが min(左, 右) の作用だ——強い側は弱い側を超えて寄与しない。

そして構造：**人生の両方向を見ねばならない。** 保持できるものは、背後*と*前の最高の支持に依存する。「良い過去／良いスキルがある」（左壁）は、右壁——健康、休息、つながりへの将来の容量——が低い時、何も語らない。人生が保持できるものを知るには両側の最大が要る。弱い方が天井だ。*それ*を上げよ。

**⚠️ アンチパターン**
*「より多く保持するには、高い壁をより高くする。」* それは `right[i]` が既に最小値の時、 `left[i]` を上げることだ。溜まる水は `min(左, 右) - height`——既に高い側を上げても何も変わらない。水位は動かない。天井ではなかった壁に努力を費やした。容量を上げる唯一の動きは*低い*壁を上げることだ。制約を最適化せよ、強みをではなく。高い壁は虚栄の指標；低い壁が真実だ。最小値を見つけよ。それを上げよ。
