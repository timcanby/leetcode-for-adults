### 34. Trapping Rain Water

> *计算下雨后杆子之间能存多少水。*

**🧩 算法**
在任意位置 `i`，能蓄住的水由两个东西决定： `i` 左边最高的杆，和 `i` 右边最高的杆。水会填到那两堵墙中**较矮**的那堵——因为矮墙是溢出的那一侧。所以：

$$\text{water}[i] = \min(\text{left\_max}[i],\ \text{right\_max}[i]) - \text{height}[i]$$

你预计算 `left_max`（从左往右跑最大值）和 `right_max`（从右往左跑最大值），然后把每个位置的存水量加起来。

```python
def trap(height):
    n = len(height)
    if n == 0:
        return 0
    left = [0] * n
    right = [0] * n
    left[0] = height[0]
    for i in range(1, n):
        left[i] = max(left[i - 1], height[i])
    right[-1] = height[-1]
    for i in range(n - 2, -1, -1):
        right[i] = max(right[i + 1], height[i])
    return sum(min(left[i], right[i]) - height[i] for i in range(n))
```

> 时间 $O(n)$ · 空间 $O(n)$

更深的原理：**一个位置蓄住的水由它的*较弱*边决定。** 不是较高的墙。不是平均。是两者的**最小值**。较高的墙与 `i` 处蓄多少水无关——你把它造到无限高，存水量也不会多一滴。只有矮墙设了上限。这是瓶颈原理，但被反转成一个*承载力*问题：capacity = min(左, 右)，强墙在弱墙之上贡献为零。

而结构：**你必须看*两个*方向，才知道什么被兜住。** `i` 处的水取决于左边最好的墙*和*右边最好的墙。单方向视角——只看左边、只看过去——对你承载力一无所知。你也需要右最大。要知道一个时刻能兜住什么，你需要知道它*两侧*的最高支撑，不只是你已经活过的那一侧。

**🏢 职场**
一个项目承载价值的能力——收入、影响、学习——受它较弱的边界限制，不是较强的那个。如果技术团队是世界级（左墙高）但 go-to-market 很弱（右墙矮），项目只兜得住弱 GTM 允许的量。往里倒更多工程不会抬升水——GTM 上限直接溢出去。

陷阱：**组织过度投资它的强项。** 强侧可见、被庆祝、好拨款。弱侧不可见、不光彩、难承认。但 capacity = min(左, 右)。强侧已经高于天花板；那里每块钱都浪费。弱侧*就是*天花板。修 GTM。工程从不是瓶颈。

而结构：**你必须双向评估。** 一个项目的真实承载力需要它后面最好的（团队、技术、历史）*和*前面最好的（市场、需求、时机）。只看左边——"我们有好技术！"——让你对右墙天花板失明。你需要两个最大值才知道项目实际能兜住什么。

**🌍 人生**
你兜住的"水"——幸福感、承载力、平静、积累的喜悦——受你*较弱*的限度限制，不是较强的那个。如果你的收入上限高到天但健康下限低，你兜不住那高收入值的量。你只兜得住健康下限允许的量。矮墙是你人生的天花板。

陷阱：**人们把高墙造得更高。** 更多收入、更多地位、更多技能——而矮墙（健康、休息、关系）原地不动。额外收入不会让你的幸福感多一滴，因为健康墙溢出去。你感觉到了：那个啥也没买到的加薪、没带来平静的升职。那就是 min(左, 右) 在起作用——强侧在弱侧之上贡献为零。

而结构：**你必须看你人生的两个方向。** 你能兜住什么取决于身后*和*身前最好的支撑。"我有好过去/好技能"（左墙）在右墙——你未来对健康、休息、连接的能力——很矮时，对你一无所知。要知道你的人生能兜住什么，两侧的最大值都要。较弱的那个是天花板。抬*那个*。

**⚠️ 反模式**
*"要兜更多，把高墙造更高。"* 那是在 `right[i]` 已经是最小值时抬高 `left[i]`。存水量是 `min(左, 右) - height`——抬高已经较高的侧什么也不变。水位不动。你把精力花在一堵从不是天花板的墙上。唯一抬升承载力的动作是抬*矮*墙。优化约束，不是强项。高墙是虚荣指标；矮墙是真相。找最小值。抬那个。
